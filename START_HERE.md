# START_HERE — с чего начать

**Репозиторий:** extella-agent-standards · **Компания:** Extella (Chariot Technologies Lab) · **Владелец:** Анвар (CEO)

## 1. Кто читает этот репозиторий

**Машина, а не человек.** Агентов Extella строят Claude, Codex и приложения, которые их создают.
Человек не читает эти документы и ничего по ним не заполняет: он говорит, что ему нужно, а
строитель делает остальное — включая паспорт агента.

## 1а. Сначала — стадия, потом всё остальное

Объём проверок задаёт **стадия стройки**: `build` — 2 гейта плюс добавки по фактам
(данные клиента, чужая машина), `prod` — 21. Спроси у машины и работай по её ответу:

```
python3 tools/stage_gates.py --stage build --json
```

Стадию не объявил — считается `prod`. Стоп-правила действуют на всех стадиях.
Старые имена `demo`/`pilot` — синонимы `build`.
Документ стадий: `BUILD_STAGES.md`, машинный источник: `stages.yaml`.

## 2. Единственная точка входа

**`AGENT_BUILD_GUIDE.md`** — прочитай его целиком, этого достаточно, чтобы построить агента.
188 строк: что такое агент Extella, девять решений при стройке, канон платформы, что выпустить
вместе с агентом и как себя проверить.

Всё остальное в репозитории — **справочники, которые подгружаются по необходимости**, а не
читаются подряд. Их список с условием «когда нужен» — в §7 гида.

Спецификацией является не текст, а **проверялки в `tools/`**: у каждой `--json` со стабильными
кодами и `--selftest`. Правило, которое нельзя проверить машинно, сформулировано в гиде как
решение при стройке, а не как требование.

## 3. Прежний порядок чтения (для человека, если он всё-таки читает)


Читать именно в этом порядке:

0. **EVOLUTION_PHILOSOPHY.md** — рамка: **почему** система устроена так. Короткий документ, но без него
   правила ниже выглядят бюрократией. Главный тезис: ценность агента создаётся не в момент создания,
   а на протяжении его жизни, поэтому наш продукт — управляемое изменение поведения.
1. **AGENT_ARCHITECTURE.md** — главный стандарт: что такое агент Extella и 25 обязательных принципов. Пока не прочитал — за агента не садишься.
2. **EXTELLA_AI_ONBOARDING.md** — как устроена платформа и её известные ловушки (где до тебя уже спотыкались).
3. **NAMING.md** — как называются части системы (Extella Evolution, Agent Passport, Agent Genome, Evolution Console / Lab / Loop). Пиши и говори этими словами — не придумывай свои.
4. **BRAND_FOR_AGENTS.md** — бренд в интерфейсе агента: какие слова запрещены, какие цвета допустимы,
   как говорит интерфейс. Проверяется машиной: `python3 tools/check_brand_copy.py <файлы>`.
5. **TEAM_PROTOCOL.md** — правила совместной работы команды: кто за что отвечает и как не мешать друг другу.

## 3. Перед началом работы

Заполни чек-лист **checklists/DoR.md** — «готов ли ты начинать».
Если хотя бы один пункт не сходится — сначала закрой его и только потом начинай.

## 3б. Готовое приложение: браузерное или серверное

Если продукт — это чужое готовое приложение, а не написанный с нуля агент,
выбирай трек по тому, как приложение устроено.

**Серверное в контейнере** (Uptime Kuma, n8n, Immich, Vaultwarden) —
**`docs/DOCKER_APP_TRACK.md`**. Там установщик одной командой, полный список
дверей песочницы окна, прокси-режим и метод диагностики белого окна за три
раунда. По добыче спроса это голова рынка, а не хвост.

**Иконка любого продукта** — **`docs/ICON_STYLE_BRONZE.md`**. Стиль один на все
плитки, делается командой `tools/bronze_icon.py <глиф> <путь>`; глифы берутся
только из `templates/lucide/`, руками не рисуются.

## 3в. Продукт с установкой одной кнопкой

Если продукт ставит что-то на машину пользователя одной кнопкой (мост к внешнему
инструменту, локальную модель, службу) — читай **INSTALLER_CANON.md**. Это
канон установщика: шесть безмодельных шагов, четыре источника токена, гейты по
железу и диску, честные отказы, версия в каждом ответе, изоляция общего кода.
Каждый пункт куплен настоящей поломкой на машине тестера, поэтому следующий
установщик получает их решёнными до первого запуска у пользователя.

## 4. Перед выпуском

Прежде чем агент попадёт к клиенту:

1. Пройди чек-лист **checklists/DoD.md** — «готов ли агент к работе у клиента».
2. Заполни паспорт агента по образцу **templates/agent_passport.yaml**.
3. Запусти проверялку:

```
python3 tools/check_agent_passport.py мой_агент.yaml
```

Она скажет, готов агент или нет, и перечислит, чего именно не хватает.
Пока проверялка не сказала «готов» — агент к клиенту не идёт.
Для Evolution Console и автоматизации используй тот же расчёт в JSON, не переписывай правила:

```
python3 tools/check_agent_passport.py мой_агент.yaml --json
```

Каждая issue содержит stable `code`, `severity`, `path`, `message_ru`, `message_en`.

## 4б. Два правила, которые забывают чаще всего

1. **Пояснение на экране.** У каждой возможности обязательна кнопка «? Как это работает» с блоками:
   как работает · что гарантировано · **чего мы НЕ обещаем** · кто может раскрыть или откатить.
   Бери готовое: `templates/help_card.md` (что писать) и `templates/help_widget.js` (готовый код окна).
2. **Русский и английский сразу.** Интерфейс, пояснения и сообщения об ошибках делаются на двух
   языках в одном выпуске. «Потом переведём» не считается сделанным.

Проверялка паспорта не пропустит выпуск, если не заполнены `limits` (границы), `help_surface`
(где пояснение) и `languages: ["ru", "en"]`.

## 4в. Agent Cabinet — появляется сам из Agent Passport

У каждого агента должен быть Agent Cabinet: Agent Passport (что заявлено), фактическое поведение
и Evolution Loop (изменение через черновик → тест → публикацию → откат).
**Руками его писать не нужно** — он собирается из Agent Passport:

```
python3 tools/build_agent_cabinet.py мой_агент.yaml --markdown
```

Если ты делаешь **автоматизацию** (то, что клиент устанавливает целиком: Агент 1С, юрист,
турагентство), а не один агент — паспорт другой:

```
python3 tools/check_automation_passport.py моя_автоматизация.yaml
python3 tools/build_automation_cabinet.py моя_автоматизация.yaml --markdown
```

Образец — `templates/automation_passport.yaml`. Платформенные агенты внутри автоматизации
описываются как **компоненты**, а не как отдельные объекты (§6 стандарта кабинета).

Стандарт кабинета и честное сравнение с Microsoft Agent 365 (что мы умеем, чего пока нет) —
`AGENT_CABINET_STANDARD.md`. Рендер интерфейса — `templates/cabinet_widget.js`.
Не заполнил границы и пояснение — кабинет не соберётся: это тот же гейт, что и на выпуске.
`agent.platform_agent_id` связывает паспорт с живым агентом. Canonical Shared Genes объявляются
стабильными `gene_id`; по отображаемому имени потребители не считаются.
