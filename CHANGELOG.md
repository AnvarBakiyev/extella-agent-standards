# История изменений

Правила репозитория: любое изменение документов — только через утверждение Анвара.
У каждой записи: дата, версия, что изменилось, кто утвердил.

## 26.07.2026 — v0.12 — архитектурно-философская рамка эволюции агентов
- `EVOLUTION_PHILOSOPHY.md`: рамка «почему так». Главный тезис: ценность агента создаётся не при
  создании, а на протяжении жизни → продукт = управляемое изменение поведения.
- Различены три природы: программу правим, чат переспрашиваем, агента развиваем.
- Определено, чем эволюция НЕ является: не самоизменение, не дообучение модели, не «автономность
  настройкой» (автономность — следствие накопленных доказательств). Формула: свобода в предложениях —
  дисциплина в активации.
- Семь принципов: доказательство важнее декларации · границы — часть возможности · немой отказ =
  худшая ложь · масштаб распространения = масштаб ответственности · обратимость даёт право на
  скорость · интеллект там, где неоднозначность · один источник правды, расхождение показываем.
- Каждый принцип привязан к живому инциденту июля 2026 (раздел «уроки, оплаченные практикой») —
  рамка выведена из практики, а не из теории.
- Разделы «чего мы сознательно не делаем», «как рамка превращается в продукт», позиционирование
  против Microsoft Agent 365 (парк против изменения) и Executive summary (EN).
- Пять открытых вопросов оставлены открытыми честно: ответственность за изменённое поведение, право
  на забвение внутри генома, наследование без слепого копирования, предел автономности, эволюция без
  владельца.
- `START_HERE.md`: рамка стала пунктом 0 порядка чтения; ссылка из `AGENT_ARCHITECTURE.md`.
Утвердил: Анвар.

## 26.07.2026 — v0.11 — архитектура названий Extella Evolution
- `NAMING.md`: продукт **Extella Evolution** (категория Agent Evolution Platform) и словарь из 9
  терминов: Agent Passport, Agent Genome, Shared Gene, Agent Cabinet, Evolution Console, Evolution
  Lab, Evolution Loop, Evolution Receipt.
- Разведены две двусмысленности: **паспорт заявляет · геном определяет · фактическое поведение
  доказывает**; Evolution Console (парк) ≠ Agent Cabinet (один агент) — иначе две админки.
- Введён термин **Shared Gene** для наследуемых элементов генома (основа экрана «используют ещё N агентов»).
- Правила: имена продукта не переводим, описания на двух языках, расшифровка «генома» при первом
  упоминании клиенту, новый термин — только через изменение NAMING.md.
- Код согласован с языком продукта: схема кабинета v1.1 (`passport.genome`, `attention.shared_genes`),
  подписи интерфейса в терминах NAMING; самопроверка генератора и рендер-тест зелёные.
- Отмечено как НЕ сделанное: проверка товарных знаков и доменов.
Утвердил: Анвар.

## 26.07.2026 — v0.10.1
- Решение Анвара по архитектуре поверхностей: **одна механика — два взгляда**. Данные и журнал
  версий в одном месте; Центр = парк/класс/риски/массовое, кабинет = один агент. Правило области
  изменения (локальное завершается в кабинете, класс — в Центре) и запрет дублирования расчётов.
  Внесено в `AGENT_CABINET_STANDARD.md` §2.4.
Утвердил: Анвар.

## 26.07.2026 — v0.10 — кабинет агента как базовая технология
- `AGENT_CABINET_STANDARD.md`: стандарт кабинета (Паспорт + Эволюция), обязательное разделение
  «как должен работать» / «как работает фактически», защита от массовой поломки при изменении
  общего механизма, честное сравнение с Microsoft Agent 365 (что есть, чего нет и почему).
- `tools/build_agent_cabinet.py`: **генератор кабинета из паспорта** — кабинет не пишется руками
  для каждого агента (самопроверка 16/16; паспорт без границ кабинета не даёт).
- `templates/cabinet_widget.js`: рендер трёх вкладок, двуязычный; защита класса задаёт буквальный
  вопрос «этот механизм используют ещё N агентов…» с выбором «локальная версия / весь класс»
  (рендер-тест 3 вкладки × 2 языка зелёный).
- Живая проверка доступности данных на аккаунте: 15 агентов, 155 знаний, 73 правила, 916 способностей.
Утвердил: Анвар.
