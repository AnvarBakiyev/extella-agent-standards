## 28.07.2026 — v0.19 — где живут реестры: источник правды в git, KV только кэш
Решение Анвара 28.07 после инцидента со скоупами KV.

- **Правило:** реестр можно хранить только там, откуда его можно пересобрать. Если потеря
  хранилища = потеря данных, это не реестр, а единственная копия.
- **Три уровня по владельцу правды**: паспорта в git (источник) → файлы устройства и контракт
  состояния (факт установки) → собранный реестр (производная, её спрашивает агент). За KV
  остаётся кэш и память агента.
- `tools/build_capability_registry.py` — сборка реестра из паспортов, схема
  `extella.capability_registry.v1`, самопроверка **10/10**, сборка воспроизводима. Проблемы не
  прячет: непройденный паспорт входит в реестр с `passport_ok: false` и кодами ошибок; один
  `automation_id` в нескольких паспортах — предупреждение; способность, объявленная несколькими
  автоматизациями, — кандидат в общие.
- Первый живой прогон: объявлено 2 автоматизации (турагентство проходит, Агент 1С нет),
  Kazakh Lawyer в реестре отсутствует, способностей объявлено 4 при 716 экспертах на аккаунте.
- §7 стандарта кабинета — новый раздел.

## 28.07.2026 — v0.18 — привязка `bound_to` (A2) и права коннекторов (A4)
Решение Анвара 28.07: из блока «нужно для денег» делаются A2 и A4; A3 и A5 сняты.

- **A2 — привязка в состоянии.** Новый гейт `tools/check_state_contract.py` (самопроверка
  **13/13**) проверяет ответ `/api/state` — как файл и как живой адрес. Обязательный блок
  `bound_to`: `hosting_profile`, `host`, `platform_profile_id`, `account_ref`, `agent_ids`,
  `since`. Три правила ловятся машинно: отсутствие поля ≠ честное `null`; секрет в состоянии
  (состояние отдаётся клиенту) — ошибка, `account_ref` только необратимый отпечаток; блок
  отдаёт факт, а не намерение — расхождение с паспортом показывает Console.
- **A2 — паспорт.** `automation.hosting_profile` (`local | server | client_server`) обязателен:
  у серверных нет каталога на диске, и без поля джанитор снёс бы их карточку как «мёртвую».
- **A4 — права коннекторов видны в паспорте.** `components.integrations[]` объявляет `scopes`
  (что именно разрешено), `personal_data` (`none | reads | stores`, умолчания нет), `retention`
  при хранении ПДн, `human_in_loop` при записи наружу («нет» — допустимый ответ, молчание — нет),
  `secret_ref` как ссылку, а не сам секрет. Корпоративный клиент проходит ИБ-проверку по паспорту,
  не читая наш код.
- `tools/check_automation_passport.py`: самопроверка **18/18 → 26/26**.
- §6 стандарта дополнен разделами 6.1 (привязка) и 6.2 (права коннекторов).
- Проверено на живом продукте: турагентство и Kazakh Lawyer отдают `bound_to`, оба проходят гейт;
  паспорт турагентства до правки гейт НЕ проходил — права двух коннекторов были не видны.

## 26.07.2026 — v0.16 — свой агент создаётся после деплоя, а не руками
- §3.27: продукт MUST получать **собственного личного агента** в Extella автоматически после
  успешного деплоя. Ручной шаг «создай агента и вставь id» ставит выпуск в зависимость от человека,
  а привязка к существующему агенту смешивает геномы двух задач.
- Восемь обязательных условий: только после успешного деплоя; идемпотентность по неизменному
  идентификатору сборки (повторный деплой читает, а не создаёт); подтверждение перечитыванием
  `agent/get` с проверкой Qwen; номер пишется в паспорт автоматически; fail-closed при неудаче;
  привязка к чужому агенту — только осознанным решением владельца; Evolution Receipt с откатом;
  создание только на своём аккаунте, `global` — никогда автоматически.
- `checklists/DoD.md`: соответствующий пункт выпуска.
- Живой случай, из которого выросло правило: Site Risk Twin ждал ручного `agent_...`, и был
  привязан к существующему агенту «Bi Agent» — геном временно общий, что и надо устранить.
Утвердил: Анвар.

## 26.07.2026 — v0.15 — Agent Cabinet обязан СОЗДАВАТЬ в Extella

  MUST создаваться все четыре вида Agent Genome — знание (Concept), правило (Rule), способность

- Восемь обязательных гарантий: тот же Evolution Loop (черновик → Evolution Lab → публикация →

  путём отката; создание НОВОГО агента в кабинете запрещено (это Evolution Console или Конструктор).
- Контракт машинный, а не текст: `tools/build_agent_cabinet.py` выдаёт блок `evolution.creation`

## 26.07.2026 — v0.12 — архитектурно-философская рамка эволюции агентов
- `EVOLUTION_PHILOSOPHY.md`: рамка «почему так». Главный тезис: ценность агента создаётся не при
  создании, а на протяжении жизни → продукт = управляемое изменение поведения.
- Различены три природы: программу правим, чат переспрашиваем, агента развиваем.
- Определено, чем эволюция НЕ является: не самоизменение, не дообучение модели, не «автономность
  настройкой» (автономность — следствие накопленных доказательств). Формула: свобода в предложениях —
  дисциплина в активации.
- Семь принципов: доказательство важнее декларации · границы — часть возможности · немой отказ =
  худшая ложь · масштаб распространения = масштаб ответственности · обратимость даёт право на
  скорость · интеллект там, где неоднозначность · один источник правды, расхождение показываем.
- Каждый принцип привязан к живому инциденту июля 2026 (раздел «уроки, оплаченные практикой») —
  рамка выведена из практики, а не из теории.
- Разделы «чего мы сознательно не делаем», «как рамка превращается в продукт», позиционирование
  против Microsoft Agent 365 (парк против изменения) и Executive summary (EN).
- Пять открытых вопросов оставлены открытыми честно: ответственность за изменённое поведение, право
  на забвение внутри генома, наследование без слепого копирования, предел автономности, эволюция без
  владельца.
- `START_HERE.md`: рамка стала пунктом 0 порядка чтения; ссылка из `AGENT_ARCHITECTURE.md`.
Утвердил: Анвар.
