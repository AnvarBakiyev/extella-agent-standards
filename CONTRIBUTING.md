# Как сюда вносить изменения

Репозиторий публичный: **видеть его может весь мир, писать — только участники
с правом записи.** Посторонний может форкнуть его себе и прислать предложение;
принять или отклонить решает владелец.

## Порядок

1. Ветка от `main`, изменение, коммит.
2. Pull request. GitHub сам прогоняет **все гейты на чистой машине**.
3. Красные гейты — слияния нет. Это не формальность: первым же прогоном на чистой
   машине нашлись два гейта, зелёных только у автора (не хватало библиотеки; тест
   ждал ответа, который бывает только на macOS).
4. Одно подтверждение — и слияние.

`main` защищена: **историю переписать нельзя, ветку удалить нельзя.** Владелец
(admin) может слить срочное напрямую — это осознанная лазейка для одного человека,
а не режим работы.

## Что проверяется само

```bash
bash tools/run_all_gates.sh
```

Прогоняй это **до** отправки: те же 29 проверок, что и в CI. Каждая проверка умеет
падать нарочно (`--selftest`) — гейт, который не умеет провалиться, не гейт.

## Три правила, которые не проверяет машина

* **Опровергнутое правило снимается не только из текста, но и из гейта.** Иначе оно
  живёт дальше и обязывает.
* **Приёмка — это то, что видит человек на экране**, а не коды ответа и наличие
  файлов. Отчёт «200 ✓ файл ✓ служба ✓» уже был правдой про каждое звено и ложью
  про целое.
* **Правка чужого файла** помечается, снимается до байта и оставляет копию рядом.

Подробности — `README.md`, канон — `DEPLOY_REQUIREMENTS.md`, порядок стройки —
`AGENT_BUILD_GUIDE.md`.

## Если ты правишь текст, а не код

Ставить git и разбираться в ветках не надо. Всё делается в браузере, пять шагов:

1. Открой файл на github.com и нажми **карандаш** (Edit this file).
2. Внеси правку.
3. Внизу — **Commit changes**. В окне выбери **Create a new branch** (GitHub предложит
   имя сам) и нажми **Propose changes**.
4. Откроется страница предложения — нажми **Create pull request**.
5. Дальше сама ничего не делай: проверки запустятся сами, придёт зелёная галочка,
   и владелец сольёт правку. Красная галочка — значит что-то в файлах разъехалось;
   напиши в чат, разберёмся.

**В коммит напиши, ЧТО изменилось и ПОЧЕМУ.** Не «правки», а «цвет состояния ошибки
привёл к палитре: #D4944A вместо синего, синего в палитре нет». Через месяц эта строка
будет единственным объяснением.

**Прямо в `main` писать нельзя** — так устроено намеренно, чтобы никто не мог задеть
чужое одним неверным нажатием. Отказ платформы на прямую запись это не ошибка, а
правило.

### Что важно знать про правила дизайна

Источник правил по облику живёт отдельно — `DESIGN_CODE.md` в корне этого репозитория
(прежние `DESIGN_RULE_FOR_APPS.md` и `UX_CANON.md` лежат в `archive/` как история), а здесь
лежит **копия** для тех, кто строит агентов. Её полноту (шрифты, палитра, шкалы, запреты)
проверяет `tools/check_design_rule.py`.

Значит правку надо вносить **в источник**, а сюда — переносить. Если поправить только
здесь, гейт покраснеет и правка не сольётся: это защита от того, чтобы два места
разъехались молча.


## Несколько чатов правят канон одновременно — два правила

Замер 22.08.2026: десять чатов работали в ОДНОЙ git-папке и в ветках назначали
H-номера по памяти. Итог — переключения ветки гонялись под ногами, чужие файлы
попадали в чужие коммиты, а H34–H39 и H51–H53 задвоились. Гейт ловит дубль только
в слитом main, между летящими ветками — молчит.

**1. Каждый чат — свой рабочий каталог (git worktree), не общая папка.**

```bash
git -C ~/Documents/Extella/extella-agent-standards worktree add \
    ~/Documents/Extella/standards-<чат> -b <чат>/canon origin/main
```

Дальше чат работает только в `standards-<чат>`. История общая (origin), а
рабочее дерево и HEAD — свои. Переключения перестают гоняться, чужие правки не
попадают в твой коммит. Свой каталог убрать по завершении:
`git worktree remove standards-<чат>`.

**2. H-номер бери у проверки, не по памяти — и с учётом летящих веток.**

```bash
python3 tools/check_canon_numbers.py --резерв
```

Отдаёт номер выше всех занятых во ВСЕХ ветках origin, не только в main. Гейт
`check_canon_numbers` (в общем прогоне) не даст влить дубль, но `--резерв` даёт
не столкнуться заранее.
