# Приложение «Разработка на Extella»

В магазине называется **Extella Guide**. Витринный гид по этим же стандартам и точка
подключения ассистентов: человек кладёт ключ Extella на свой компьютер одной кнопкой, копирует
промпт и отдаёт его Claude Code или Codex. Первый кадр остаётся обычной страницей и открывается
без модели.

| | |
|---|---|
| версия | 3.9.1, цена 0 (число берётся из listing.json — руками не писать) |
| состояние | опубликовано; `published` принадлежит листингу |
| состав | page + 12 Expert + архив моста Claude |
| права | `expert.run` + `device.run` + `api.full` |
| выпуск версии | `product/deploy_prerelease_claude.py`; `product/deploy_product.py` — старый, для 3.0.x, не запускать |

H20 действует здесь буквально: добавление версии к этому листингу немедленно видно всем.
Для эксперимента нужен отдельный непубличный листинг; для новой версии живого продукта —
отдельная отмашка владельца до `add-version`.

## Что умеет приложение

Пять экранов в строке вкладок, переключатель языка RU/EN там же. Начальный экран
остаётся прежним.

**«Начало»** — главный сценарий:
* **Выбор «Где ты будешь работать?»** (оболочка 6, аудит Guide 26.10.2026): Claude Code на этом
  компьютере, Codex на этом компьютере или обычный чат / облако. Для чата кнопка ключа гаснет и
  страница честно говорит, что проверенного пути нет. Выбор первой строкой уходит в промпт.
* **«Подготовить ключ на этом компьютере»** — эксперт `dev_connect_assistant` сначала разведывает
  (`проверить_только`, ничего не меняет): называет компьютер и номер устройства из `device.txt`.
  Человек подтверждает «Да, этот компьютер» или вводит другой Device ID, и выпуск идёт с
  `targets` и `ожидаемое_устройство`: ответило другое устройство — отказ до изменений. Лежащий
  ключ другого аккаунта не выдаётся за готовый и заменяется только по кнопке. Ключ через прокси
  ОС (`/api/ext/core`, право `api.full`), в `~/.extella/api_token.txt`, проверен живым вызовом;
  в окно не приходит. Под кнопкой четыре шага: ключ → клиент настроен → перезапуск → вызов
  `list_profiles`. Страница отмечает только первый: канала из клиента у неё нет, последний шаг
  проверяется в самом клиенте. Каждая попытка нумеруется — ответ прежней не меняет новую.
  Эксперт старой установки (без `версия_эксперта`) получает прежний вызов, а окно пишет
  «устройство не сверено, обнови приложение». Вызов дольше ~51 с доделывается в фоне;
* **«Скопировать промпт для агента»** — главная кнопка: промпт со ссылкой на правила, агент
  читает их сам;
* «что нового» и предупреждение об устаревшей оболочке: содержимое объявляет
  `оболочка_минимум`, и если страница старше — приложение говорит это словами.

**«Попробовать»** — «День первый»: семь актов, которые разбирают папку Загрузки на этом
компьютере с откатом каждого шага. Эксперты `journey_*` и `local_model_ask`.

**«Конструктор»** — обзор платформы как AI-LEGO: шесть объёмных деталей с описаниями,
рабочий стол, чат и пример API, шесть сценариев сборки. Сборка и разборка деталей,
описания и переключение способов работы выполняются в странице. Пример API только
копируется; вкладка не вызывает Expert и не получает ключ. Изображения встроены,
видео и анимация чата загружаются с официальных сайтов только по нажатию.
Раздел работает на русском и английском, поддерживает клавиатуру и уменьшение анимации.

**«Найти ответ»** — все разделы руководства, складные, и поиск с подсветкой по всему тексту.
Клавиша `/` — в поиск, `Esc` — сбросить.

**«Ещё»** — «Проверить обновление» (тот же путь, что работает в фоне: двух механизмов быть не
должно, иначе один однажды соврёт), «Что нового», «Скопировать весь текст».

Эксперты установки `extella_codex_product_setup`, `extella_claude_product_setup` и
`extella_local_llm_product_setup` и архив моста приложены к версии, но страница их не
вызывает: прежняя кнопка «Подключить Codex» с пятью этапами снята, её место заняла кнопка
подключения.

Агенту в облаке (Codex Cloud, Claude Code в вебе, Codespaces) кнопка не поможет: она кладёт
ключ на компьютер. Для облака ключ задаётся переменной `EXTELLA_API_TOKEN` в настройках
окружения; `tools/connect_mcp.py` узнаёт облачную среду и говорит это сам.

## Где что лежит

| файл | что в нём |
|---|---|
| `content.json` | весь текст разделов на двух языках: `тело` и `тело_en`, отпечатки перевода |
| `shell.json` | строки интерфейса на двух языках: кнопки, сообщения, исходы кнопки подключения |
| `page.template.html` | вёрстка и скрипты; из него и двух JSON `build.py` собирает `index.html` |
| `constructor.ts`, `constructor.css` | поведение и стили отдельной вкладки «Конструктор», встраиваются сборщиком |
| `assets/desktop.jpg`, `assets/chat-poster.png` | встроенные постеры официального рабочего стола и чата |
| `constructor.tsconfig.json`, `package.json` | строгая проверка TypeScript; браузеру зависимости не нужны |
| `index.html` | собранная страница — руками не править |
| `выпуски_содержимого.json` | журнал выпусков содержимого (`check_content_release.py --записать`) |
| `listing.json` | паспорт: версия, права, `version_id` живой версии, Expert вне папки |
| `update.py` | замена страницы у живой версии на месте |
| `product/deploy_prerelease_claude.py` | новая версия: страница + все Expert + архив |
| `test_page_contract.mjs` | контракт страницы: `node --test store_app/test_page_contract.mjs` |
| `../experts/dev_connect_assistant.py` | эксперт кнопки подключения |
| `../experts/journey_*.py`, `local_model_ask.py` | эксперты «Дня первого» |

**Версии раздельные:** `ВЕРСИЯ_ОБОЛОЧКИ` в шаблоне растёт при правке самой страницы,
`версия_содержимого` в данных — при правке текста. Обновление применяется **только если строго
новее** (H14): иначе отставший источник откатывает свежий снимок — этот дефект был и исправлен.

Конструктору нужна оболочка 5. Разметка находится в разделе с ролью `конструктор`
в `content.json`, поэтому проходит те же проверки перевода и выпуска, что и руководство.
Этот раздел не попадает в список поиска. Оболочка 4 тоже читает main: для неё в разделе
остаётся обычный текст со ссылкой на карту и предложением обновить приложение, а новая
разметка находится внутри неактивного `template`. Подготовка PR сама по себе не обновляет магазин.

Сборка требует Python 3, Node.js 22.18 или новее и зависимости из закреплённого lock-файла.
TypeScript компилируется в обычный JS; React, CDN-скрипты и загрузчик модулей странице
не нужны. Проверка типов отдельно:

```bash
npm --prefix store_app ci
npm --prefix store_app run typecheck
python3 store_app/build.py
```

Шрифты конструктора берутся из `assets/extella-fonts.css` в корне репозитория и
встраиваются в HTML. Постер стола — `https://extella.dev/apps/one-environment.jpg`,
постер чата — первый кадр `https://extella.ai/images/demo_message_white.gif`.
Исходные публичные материалы: `https://extella.dev/map/` и страницы, указанные в описаниях
деталей. Сценарии роботов и IoT обозначены как варианты сборки, а не готовые устройства.

## Кто может обновлять

Текст меняется коммитом в `content.json`: это единственный источник, а оболочка читает его
публично без токена. Оболочка или Expert меняются только после сборки и гейтов. Любое изменение
живой версии или добавление следующей версии публично сразу и требует решения владельца.

Правка текста — всегда обе стороны, русская и английская, затем:

```bash
python3 tools/check_translation.py --отпечатки store_app/content.json
python3 tools/check_content_release.py --записать
```

Если меняется смысл — строка в `что_нового` на двух языках и новая `версия_содержимого`.

## Три способа обновить, от дешёвого к дорогому

| что меняется | что делать | что нужно от человека | как быстро видно |
|---|---|---|---|
| **текст, данные** | коммит в `content.json` | ничего | до 5 минут (кэш GitHub) |
| **оболочка, вёрстка, скрипты** | `build.py`, гейты, затем `update.py` — замена страницы у живой версии | отдельная отмашка | при следующем открытии окна |
| **Expert** | новая версия через `deploy_prerelease_claude.py` | отдельная отмашка; покупатели переустанавливают | после переустановки |

Первый способ — тот самый «поправил у себя, обновилось у всех»: страница читает
`content.json` прямо из этого репозитория (`raw.githubusercontent.com` отдаёт
`access-control-allow-origin: *`, поэтому песочнице токен не нужен). Проверено живьём
13.08.2026: коммит только в содержимое → окно показало новый раздел и отметило
«обновлено до 2026-08-13.2», хотя `index.html` не пересобирался и в магазин не загружался.

**Ограничение честно:** GitHub держит свой кэш **пять минут**, и ни `no-cache`, ни параметр
в адресе его не пробивают (`source-age` в ответе это показывает). Для руководства это
нормально; для данных, которые обязаны быть свежими за секунды, такой источник не годится.

**Снимок в странице обязателен.** Первый кадр рисуется из встроенной копии — мгновенно и без
сети. Если бы страница ждала сеть, она показывала бы пустой экран при недоступном GitHub,
а это дефект по нашему же стоп-правилу.

## Как обновить оболочку или Expert

Перед любым релизом:

```bash
python3 store_app/build.py
python3 tools/check_ui_api_contract.py store_app
python3 tools/check_app_scopes.py store_app
bash tools/run_all_gates.sh
```

Плюс контракт страницы: `node --test store_app/test_page_contract.mjs`. В общем прогоне
гейтов красный «классы поверхностей» читает плагины машины, на которой запущен, и падает и на
чистом main — остальные обязаны быть зелёными.

`build.py` проверяет данные и разметку до магазина. UI-гейт сверяет маршрут страницы с
серверной поверхностью; гейт прав выводит нужные права из страницы и Expert — своих в папке
и перечисленных в `listing.json` полем `эксперты_вне_папки`. Добавил Expert в
`deploy_prerelease_claude.py` — допиши его и туда, иначе гейт его не увидит.

**Только страница** (вёрстка, `shell.json`, снимок текста): `python3 store_app/update.py`
меняет страницу у живой версии, перепокупка не нужна. Скрипт сверяет отданную страницу с файлом
посимвольно (без вставок платформы: `<base href>` и пропуск окна) и отказывается докладывать
«обновлена», если они расходятся. Частая причина расхождения — `version_id` в `listing.json`
смотрит не на последнюю версию.

**Expert:** новая версия через `product/deploy_prerelease_claude.py`. Без флагов он показывает
план; `--выполнить` создаёт отдельный непубличный листинг для проверки; `--выполнить
--в-живой-листинг` добавляет версию к живому — она публична сразу (H20), только после решения
владельца. Эксперт моста Claude живёт в соседнем репозитории (`~/Documents/Codex/extella-codex-bridge`);
если там идёт незакоммиченная работа — `--без-моста-claude`, в агенте останется прежняя копия.

**Покупатели получают новый Expert только переустановкой.** Агент приложения — снимок на момент
установки: окно, открытое после выпуска, по-прежнему видит старый набор, и новый Expert
отвечает «не найден». Кнопка в этом случае просит удалить Guide со стола и поставить заново
из магазина.

## Почему три права

Чтение гида, поиск, сравнение версии и статус остаются в странице и не запускают модель.
Expert нужен только для работы на машине покупателя: подключить редактор и провести «День
первый». Отсюда `expert.run` для запуска Expert и `device.run` для работы на устройстве.

`api.full` — ради одной кнопки подключения. Платформа ключ эксперту не передаёт (замер
28–29.09.2026, Mac и VPS), а с этим правом пропуск окна открывает прокси ядра `/api/ext/core`:
эксперт выпускает ключ, привязанный к основному агенту аккаунта `agent_extella_default`, и сразу
пишет его в файл. Право видно покупателю в карточке; без него кнопка отвечает словами «право не
выдано». **Не снимать**: гейт прав без `api.full` теперь падает.

## Иконка

`icon.png` (512×512, из `icon.svg`) — линейный знак раскрытого руководства: бумага `#FAF9F5`,
чернила `#0A0A0A`, строки акцентом `#C57E33`. Ни градиентов, ни теней, ни эмодзи — палитра
светлой темы правила по дизайну. Проверена читаемость на 96 px: знак не слипается.

**Это заглушка, а не фирменный знак.** Своя графика — решение по дизайну; когда она даст свой
вариант, заменить файл и приложить заново.

Иконка правится **в карточке, а не в версии**: `Edit` у листинга → поле `Icon`. Новой версии
и перепубликации не требует.

## Состояние

Рабочая публичная версия — 3.9.1 (источник — `listing.json`), выпуск 27.10.2026: заметная строка «куда
вставлять промпт» и вход в терминале; до неё — подключение нового пользователя по аудиту Guide, оболочка 6. Предыдущая версия выпущена 29.09.2026; её кнопка
подключения проверена в настоящем окне: Mac — ключ уже на месте, новый не выпущен; Windows 11 —
ключ выпущен через запасное поле Device ID, повтор без Device ID — «уже на месте»; долгий вызов
ушёл в фон, повтор прошёл. Страница после выпуска обновлялась `update.py` (последний раз —
содержимое 2026-10-02.1). Ключ ни разу не выводился.
