# Приложение «Разработка на Extella»

Витринный гид по этим же стандартам. Тип продукта — **только страница**: ни агента,
ни архива, ни прав приложения. Отсюда его главное свойство: открывается мгновенно,
не показывает диалогов согласия и не может ничего сломать у покупателя.

Публикация из чата служебным токеном ушла в **чужой контейнер витрины** и в интерфейсе
владельца не появилась (разбор — H13 в `DEPLOY_REQUIREMENTS.md`: витрина принадлежит хешу
токена, а не аккаунту). Тот листинг удалён. Правильный путь — владелец кладёт `index.html`
в поле **Web page** формы публикации: тогда листинг по построению попадает в его контейнер.
После публикации впиши сюда `listing_id` и `version_id` — их ждёт `update.py`.

## Что умеет приложение

* складные разделы и поиск с подсветкой по всему тексту;
* **«Скопировать всё руководство»** — весь канон простым текстом одной вставкой в своего
  ассистента. Это главный сценарий продукта, поэтому кнопка главная;
* **«Что нового»** — список изменений из того же файла содержимого;
* **«Проверить обновление»** — тот же путь, что работает в фоне (двух механизмов быть не
  должно, иначе один однажды соврёт), с видимым ожиданием и честным отказом;
* **предупреждение об устаревшей оболочке**: содержимое объявляет `оболочка_минимум`, и если
  страница старше — приложение говорит это словами, а не рисует текст наполовину;
* клавиша `/` — в поиск, `Esc` — сбросить.

**Версии раздельные:** `ВЕРСИЯ_ОБОЛОЧКИ` в шаблоне растёт при правке самой страницы,
`версия_содержимого` в данных — при правке текста. Обновление применяется **только если строго
новее** (H14): иначе отставший источник откатывает свежий снимок — этот дефект был и исправлен.

## Кто может обновлять

**Поправка 13.08.2026: изоляции по токену больше нет** (H13 отменён). Токен устройства видит
витрину аккаунта целиком, поэтому `update.py` работает и без отдельного файла с токеном.

Два пути, оба рабочие:

* **одной командой:** `python3 update.py` — заменяет страницу у той же версии;
* **вручную:** `Edit` у карточки → поле `Web page` → новый `index.html`.

Отдельный файл `~/.extella/os_token.txt` скрипт по-прежнему читает первым, если он есть, —
это остаётся способом указать конкретный токен, но обязательным больше не является.

## Три способа обновить, от дешёвого к дорогому

| что меняется | что делать | что нужно от человека | как быстро видно |
|---|---|---|---|
| **текст, данные** | коммит в `content.json` | ничего | до 5 минут (кэш GitHub) |
| **оболочка, вёрстка, скрипты** | `build.py`, потом замена страницы | приложить файл в форме | сразу |
| **и то и другое** | `build.py` + коммит + замена | приложить файл | сразу |

Первый способ — тот самый «поправил у себя, обновилось у всех»: страница читает
`content.json` прямо из этого репозитория (`raw.githubusercontent.com` отдаёт
`access-control-allow-origin: *`, поэтому песочнице токен не нужен). Проверено живьём
13.08.2026: коммит только в содержимое → окно показало новый раздел и отметило
«обновлено до 2026-08-13.2», хотя `index.html` не пересобирался и в магазин не загружался.

**Ограничение честно:** GitHub держит свой кэш **пять минут**, и ни `no-cache`, ни параметр
в адресе его не пробивают (`source-age` в ответе это показывает). Для руководства это
нормально; для данных, которые обязаны быть свежими за секунды, такой источник не годится.

**Снимок в странице обязателен.** Первый кадр рисуется из встроенной копии — мгновенно и без
сети. Если бы страница ждала сеть, она показывала бы пустой экран при недоступном GitHub,
а это дефект по нашему же стоп-правилу.

## Как обновить оболочку

Правишь `index.html`, потом одна команда:

```bash
python3 update.py
```

Требует `listing_id` и `version_id` в `listing.json` — их видно после публикации.

Страница заменяется **у той же версии**: новой версии не появляется, перепокупка не
нужна, покупатели видят новый текст при следующем открытии окна. `--status` показывает
состояние листинга, ничего не меняя.

Скрипт проверяет файл **до** отправки (заголовок, закрытые разделы, конец файла,
отсутствие меток подстановки) и сверяет отданное платформой после. Обе проверки
проверены на падение: обрезанный файл до платформы не доходит.

## Почему без агента

Гид ничего не вызывает — значит `app_scopes` пусты по делу, а не по забывчивости.
Если однажды понадобится живое обновление содержимого без замены файла, придётся
приложить агента и попросить `kv.read`; это добавит покупателю диалог согласия и
2–3 секунды ожидания. Для документации обмен невыгодный.

## Иконка

`icon.png` (512×512, из `icon.svg`) — линейный знак раскрытого руководства: бумага `#FAF9F5`,
чернила `#0A0A0A`, строки акцентом `#C57E33`. Ни градиентов, ни теней, ни эмодзи — палитра
светлой темы правила по дизайну. Проверена читаемость на 96 px: знак не слипается.

**Это заглушка, а не фирменный знак.** Своя графика — решение Эллы; когда она даст свой
вариант, заменить файл и приложить заново.

Иконка правится **в карточке, а не в версии**: `Edit` у листинга → поле `Icon`. Новой версии
и перепубликации не требует.
