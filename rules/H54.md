# H54. `app-agent/run` СИНХРОНЕН: эксперт возвращает терминал значением, не задачей

Свод целиком — `DEPLOY_REQUIREMENTS.md`; оглавление правил — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H54. `app-agent/run` СИНХРОНЕН: эксперт возвращает терминал значением, не задачей

**Разбор с чатом коллеги, 22.08.2026.** `app-agent/run` — сахар над `expert.run`, и он
**ждёт возврат эксперта синхронно**, а потом ретранслирует его значение странице. Замеры:
без закрепления вернул устройство и его данные за 17,3 с; несуществующий эксперт —
терминальную ошибку «Expert not found» за 3656 мс. Отдельного флага «ждать» нет, ожидание
и так встроено.

**Отсюда корень частой ошибки.** Если страница получает NON_TERMINAL — это не платформа
вернула рано, а **device-эксперт вернул нетерминал**: создал внутреннюю задачу и отдал
хэндл, вместо того чтобы блокироваться и вернуть готовый результат. `app-agent/run` честно
ретранслирует то, что вернул эксперт.

Правило: **эксперт на устройстве возвращает терминальный результат ЗНАЧЕНИЕМ функции** —
делает работу inline и возвращает готовое. Никаких внутренних task + waiter: ожиданием
служит собственное ожидание платформы внутри `app-agent/run`. Тогда один scoped
`app_token`-вызов даёт терминал без browser polling, без `task_id` в браузере, без
`api.full` и без второго запуска эксперта.

Точная форма:
```
POST /api/app-agent/run     header X-App-Token: {{app_token}}     scope expert.run
body:     {"app_token": "<короткоживущий ключ>", "expert_name": "<эксперт>",
           "params": {...}, "targets": ["<device_id>"]}  # targets требует device.run
response: возвращённое значение эксперта, снятое с транспортной обёртки; вызов блокируется
```
База — `POST /api/app-agent/call {op:"expert.run", payload:{...}}`. Поле `global`
в scoped-канале не допускается. `targets` сохраняется только при отдельно выданном
`device.run`; без него шлюз удаляет закрепление, и эксперт уходит в контейнер. Порядок
определения и закрепления устройства задан H106.

**Единственная граница.** У `app-agent/run` есть таймаут: работа длиннее него не успеет
вернуть терминал, и страница снова получит нетерминал. Это уже пробел платформы — scoped
task-check по `app_token` (передан платформенной команде). Но чаще эксперт возвращается
рано и быстро — это async-эксперт, лечится синхронным возвратом, а не ожиданием платформы.
