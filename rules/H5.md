# H5. Страница МОЖЕТ позвать своего агента — через app-token

Свод целиком — `DEPLOY_REQUIREMENTS.md`; оглавление правил — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H5. Страница МОЖЕТ позвать своего агента — через app-token

**Ограничение снято платформой 12.08.2026.** Прежняя редакция этого раздела говорила
«из страницы нельзя вызвать ни агента, ни эксперта» — это было верно ровно до появления
механизма `app_token`. Замерено живой пробой в тот же день.

**Подтверждено вторично 19.08.2026, чужим замером на гибридном продукте.** Тот же вывод
пришёл независимо: страница получает снимок состояния одним вызовом эксперта на
закреплённом устройстве, для чего нужны права запуска эксперта и обращения к устройству.
Оговорка из того же замера: подробные местные действия всё равно остаются в архивной
части — со страницы делается снимок, а не работа.

**Как это работает.** В index подставляется `{{app_token}}` — зашифрованная истекающая
capability (TTL 2 часа, обновляется перезагрузкой страницы), внутри связка
`{токен, listing_id, срок}`. Её принимают два узких эндпоинта:

| Эндпоинт | Тело | Что делает |
|---|---|---|
| `POST /api/app-agent/run` | `{app_token, expert_name, params}` | запуск эксперта своего агента |
| `POST /api/app-agent/message` | `{app_token, payload}` | диалог с агентом |

Привязка перечитывается на каждом вызове из покупки и прибивается заголовком — до чужих
агентов не дотянуться. Лимиты: 30 вызовов за 60 с, тело ≤ 64 КБ. Утечка app-токена стоит
атакующему только «агент этого приложения до истечения срока», не аккаунт.

**Замер (живая проба, страничный продукт, предрелиз):**

| Проверка | Результат |
|---|---|
| `{{app_token}}` подставлен | да, 204 символа |
| `app-agent/run` с несуществующим экспертом | **канал открыт**: 3 656 мс, ответ ядра «Expert not found» |
| `app-agent/message` | **не работает**: `422 {'loc':['body','agent_id']}` — см. ниже |
| Ядро напрямую (`api.extella.ai`) | закрыт, и правильно: CORS для страниц не открывали |
| API самой ОС | 200 |

**Что это меняет для выбора типа.** Вопрос «интерфейс зовёт агента или экспертов?» больше
не отправляет продукт автоматически в устройственный канал: страничный продукт теперь
тоже это умеет. Решающим остаётся первый вопрос — **нужно ли что-то на компьютере
пользователя** (локальные файлы, 1С, службы). Данные на машине → устройственный; логика
в браузере или в способностях агента → страничный.

**Два открытых наблюдения (сообщены автору платформы 12.08.2026):**

1. `app-agent/message` падает всегда: ядро требует `agent_id` не только заголовком, но и
   в теле запроса. Тот же класс, что уже встречавшаяся ошибка с `agent/run`.
2. **`{{token}}` подставляется в index безусловно** — независимо от `page_headers`.
   Странице приходит полный токен аккаунта покупателя (36 символов, тот же, которым
   открывается ядро). То есть продавец, написавший `{{token}}` в своей странице, получает
   токен покупателя целиком. Пока это так — **в своих продуктах пользуйтесь `{{app_token}}`
   и не запрашивайте `{{token}}` вовсе**: он вам не нужен, а ответственность за него
   несёте вы.
