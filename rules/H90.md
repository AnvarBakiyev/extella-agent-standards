# H90. «Действий человека — ноль» написано по macOS: на Windows токен на диск не пишется

Свод целиком — `DEPLOY_REQUIREMENTS.md`; оглавление правил — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H90. «Действий человека — ноль» написано по macOS: на Windows токен на диск не пишется

Замер с коллегой на Windows: приложение открыто, вход выполнен, слушатель жив
(uvx, python, десять процессов) — но эта сборка кладёт в `~/.extella` только
`device.txt`. Токен `os.extella.ai` живёт в памяти приложения и уходит заголовком
в запросы; на диск, в отличие от macOS, не пишется. Скрипт подключения
(`platform_client.py`) ищет `~/.extella/os_token.txt` — и, не найдя, раньше врал
«открой приложение, файл появится сам», хотя приложение уже открыто.

**Правило.** Обещание «действий человека — ноль» держится только там, где токен
на диск кладёт сам компонент платформы; это macOS. На Windows такого компонента
нет — обещание ложно, и это пробел платформы, а не поломка машины. Пока сборка не
выровнена:

- скрипт обязан **честно** сказать, что файла нет и почему (`platform_client.py`
  уже исправлен), а не советовать бесполезное «открой приложение»;
- прежде чем гнать человека в консоль браузера, проверить, не персистит ли
  приложение вход в своём хранилище (на Windows — `%APPDATA%`): отсутствие строки
  `os_token` в коде приложения не доказывает, что токена нет на диске под другим
  именем. Если он там есть, его читает эксперт на уже авторизованном устройстве —
  ноль шагов человека;
- ручной посев файла (консоль → буфер → файл) — крайнее средство, один раз, и
  значение токена не печатается ни в чат, ни на экран.

Правильная починка — на стороне сборки: приложение Windows должно писать токен на
диск так же, как macOS. Тогда «ноль действий» станет правдой (пункт письма
платформе).
