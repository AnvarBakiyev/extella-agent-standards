### H81. Вход противоречил промпту, и побеждал вход

**Замер 26.08.2026.** Готовый промпт запрещал: «не проси переслать токен в чат».
README, шаг 1, велел ровно обратное: «попроси пользователя написать в чате
Extella „Сгенерируй мне API-токен“, пусть пришлёт строку тебе». Противоречие
внутри единственного входа — и **побеждал README**, потому что промпт сам
отправляет агента читать README как источник правды. Человек, не знающий
Extella, упирался в тупик: где чат, что писать, куда вставлять секрет.

**Просить было не нужно вовсе.** Ключ появляется на диске сам при первом запуске
приложения (`~/.extella/os_token.txt`, 600), и это ТОТ ЖЕ ключ, который нужен
MCP — подтверждено рукопожатием `initialize` с `api.extella.ai/mcp/`. Экрана
«выдать токен» не существует: `token/list` на живом аккаунте отдаёт ноль
созданных вручную ключей.

**Норма.** Шаг, который человек не может выполнить без знания платформы, —
это не инструкция, а команда: `tools/connect_mcp.py`. Три правила внутри:
1. **Ключ проверяется работой, а не наличием файла.** Файл переживает смену
   аккаунта; рукопожатие — единственное честное доказательство.
2. **Секрет не ложится ни в конфиг, ни в аргументы.** У Claude Code для этого
   есть `headersHelper` — скрипт отдаёт заголовки в момент вызова. У Codex его
   нет, ключ идёт в `~/.codex/config.toml` — файл переводится в 600, и об этом
   сказано вслух, а не умолчано.
3. **Уже настроенное не переписывается**: у человека может быть связка на
   другой аккаунт.

**Мелочь, стоившая бы тишины.** `claude mcp add-json` без `--scope user`
записывает сервер в область ТЕКУЩЕЙ папки (`projects.<cwd>` в `~/.claude.json`).
Агент отчитался бы «подключено», а в любой другой папке связки бы не было.

**Заодно исправлен формат для Codex.** README показывал ему JSON `mcpServers` —
это формат Claude Code. Codex держит MCP в TOML `[mcp_servers.*]`
(`~/.codex/config.toml`); по прежнему примеру он не подключался.
