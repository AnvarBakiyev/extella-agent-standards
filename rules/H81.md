### H81. Вход противоречил промпту, и побеждал вход

**Замер 26.08.2026.** Готовый промпт запрещал: «не проси переслать токен в чат».
README, шаг 1, велел ровно обратное: «попроси пользователя написать в чате
Extella „Сгенерируй мне API-токен“, пусть пришлёт строку тебе». Противоречие
внутри единственного входа — и **побеждал README**, потому что промпт сам
отправляет агента читать README как источник правды. Человек, не знающий
Extella, упирался в тупик: где чат, что писать, куда вставлять секрет.

**Просить было не нужно вовсе.** Ключ нужен тот же, что у MCP.

> **ПОПРАВКА 28.09.2026 — два утверждения этого абзаца оказались неверны.**
> Первое: ключ на диске сам НЕ появляется — приложение 1.3.0 его не кладёт, а
> экран выдачи есть (`Library → System → Tokens`), см. H108 и замер 24.09.2026.
> Второе, и оно дороже: **рукопожатие ничего не подтверждает.** `initialize` с
> заведомо неверным ключом отвечает HTTP 200 и `"result"`, а `tools/list`
> отдаёт каталог инструментов вовсе без авторизации. Проверка, построенная на
> подстроке `"result"`, объявляла «подключено» на любой строке вместо ключа —
> и новичок уходил искать поломку там, где её нет (аудит 28.09.2026, F01).
> Доказательство ровно одно: **вызов читающего инструмента и разбор ответа по
> полям** (`isError`, `error`). Пустой список нового аккаунта — законный успех.

**Норма.** Шаг, который человек не может выполнить без знания платформы, —
это не инструкция, а команда: `tools/connect_mcp.py`. Три правила внутри:
1. **Ключ проверяется вызовом, а не наличием файла и не рукопожатием.** Файл
   переживает смену аккаунта, а рукопожатие проходит с любым мусором вместо
   ключа. Честное доказательство — `tools/call` читающего инструмента с
   разбором `isError`.
1-бис. **В заголовках обязателен `X-Agent-Id`.** Замер 28.09.2026: тот же вызов
   с верным ключом, но без этого заголовка отвечает `isError: true` и текстом
   «Failed to resolve dependency 'token'» — сообщение винит ключ, хотя ключ
   верен. Заголовку достаточно быть непустым (несуществующий идентификатор даёт
   тот же ответ, что настоящий — проверено на `list_agents`; инструменты,
   работающие В области агента, требуют настоящего). Поэтому подключиться можно
   и на пустом аккаунте, а своего агента человек заводит после.
   **Один текст на две причины:** тем же словом Extella отвечает и на неверный
   ключ, и на пустой заголовок агента — различить их по ответу нельзя, поэтому
   наш код всегда шлёт непустой агент и трактует этот отказ как отказ по ключу.
2. **Секрет не ложится ни в конфиг, ни в аргументы.** У Claude Code для этого
   есть `headersHelper` — скрипт отдаёт заголовки в момент вызова. У Codex его
   нет, ключ идёт в `~/.codex/config.toml` — файл переводится в 600, и об этом
   сказано вслух, а не умолчано.
3. **Уже настроенное не переписывается**: у человека может быть связка на
   другой аккаунт.

**Мелочь, стоившая бы тишины.** `claude mcp add-json` без `--scope user`
записывает сервер в область ТЕКУЩЕЙ папки (`projects.<cwd>` в `~/.claude.json`).
Агент отчитался бы «подключено», а в любой другой папке связки бы не было.

**Заодно исправлен формат для Codex.** README показывал ему JSON `mcpServers` —
это формат Claude Code. Codex держит MCP в TOML `[mcp_servers.*]`
(`~/.codex/config.toml`); по прежнему примеру он не подключался.
