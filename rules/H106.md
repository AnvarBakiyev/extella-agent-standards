# H106. СТРАНИЦА ОС ВЫЗЫВАЕТ ЭКСПЕРТА ЧЕРЕЗ APP_TOKEN, НЕ ЧЕРЕЗ TOOLBAR-МОСТ

Свод целиком — `DEPLOY_REQUIREMENTS.md`; оглавление правил — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H106. СТРАНИЦА ОС ВЫЗЫВАЕТ ЭКСПЕРТА ЧЕРЕЗ APP_TOKEN, НЕ ЧЕРЕЗ TOOLBAR-МОСТ

**Живой замер 22.09.2026 в настоящем окне Extella OS через отладочный порт** (двумя
исполнителями независимо: хранитель канона и чат Codex). В
`desktop.*.js` нет обработчика `etb_run_expert`; `etb_init` несёт только
`{theme, lang}`; кадр страницы имеет `origin: null`, поэтому обращение к
`parent.extellaDesktop` заканчивается `SecurityError`. Протокол `etb_*` принадлежал
снятому 12.08 тулбару. Страница, созданная на нём, выглядит целой, но её кнопки
не могут вызвать эксперта.

**Рабочий контракт (сверен с Агентом 1С и Рекрутёром):**

1. В `index.html` объявить `{{app_token}}`. Полный `{{token}}` не запрашивать.
2. Все вызовы делать `POST https://os.extella.ai/api/app-agent/run` с телом
   `{app_token, expert_name, params, targets?}`. Никаких сообщений родительскому
   окну и чтения его JavaScript API.
3. Первый вызов эксперта-диспетчера отправлять **без `targets`**. Из ответа взять
   `pageRoute.targetId`; запасной вариант — `device`/`device_id` в транспортном
   конверте.
4. Все последующие вызовы отправлять с `targets: [полученное устройство]`. Если
   первый ответ не содержит устройства, показать человеку конкретную причину и
   оставить повтор доступным.
5. Запрашивать права `expert.run` и `device.run`. Соблюдать границы канала:
   30 вызовов за 60 секунд, тело до 64 КБ, TTL app-token два часа (обновляется
   перезагрузкой окна), синхронный терминальный ответ по H54.

**Временный обход §46 до исправления выбора устройства платформой.** Если первый
вызов без `targets` вернул `[Execution Error] ... (<container>, line 1)`, это подпись
H104: платформа выбрала компьютер, чей листенер вошёл в другой аккаунт. Приложение
обязано объяснить это словами, показать поле Device ID и кнопку «Работать через это
устройство», затем проверить диспетчер явным `targets: [device_id]`. Device ID хранится
только в памяти открытого окна: `localStorage` в песочнице бросает `SecurityError`, поэтому
при следующем открытии человек вводит его заново. На других ошибках поле не показывать.
Этот путь принят в живом окне Агента 1С 1.66.0 и повторно проверен предрелизом H106
22.09.2026.

**Машинная охрана.** Генератор `tools/new_product.py --thin` и рецепт
`templates/app-recipe` обязаны содержать `{{app_token}}` и `app-agent/run`, а
порождённая страница не должна содержать `etb_run_expert` или
`parent.extellaDesktop`. Гейт обязан ссылаться на номер `H106`, иначе правило не
считается покрытым.

**Приёмка.** Только настоящее окно ОС: закрытый предрелиз → ярлык рабочего стола →
первый вызов вернул id открытого устройства → второй вызов с этим id вернул имя
той же машины. Стенд-имитация и прямой HTTP-запрос полезны до выпуска, но эту
приёмку не заменяют.

**Замер изнутри кадра окна:**

| Что проверено | Результат |
|---|---|
| `etb_init` от ОС | только `{theme, lang}` — устройства нет |
| обработчик `etb_run_expert` в сборке ОС (`desktop.*.js`) | **0 упоминаний** — вызов уходит в пустоту |
| `getDeviceID` в сборке ОС | 0 упоминаний |
| кадр окна приложения | песочница, `origin = null` |
| `parent.extellaDesktop` из кадра | **SecurityError** — браузер не пускает |
| сам рабочий стол ОС | `extellaDesktop.getDeviceID()` есть, отдаёт UUID — но окну приложения недоступен |

**Первый вызов без `targets` — куда он уходит.** Замер 22.09 в окне пробы (листинг
`40cf6ccf…`, эксперт `h106probe_where`, один и тот же `app_token`):

| `targets` | результат |
|---|---|
| нет | `invalid decimal literal (<container>, line 1)` |
| `39f81469…` («Windows с 1С», листенер вошёл в другой аккаунт) | та же ошибка, дословно |
| `85800354…` (VPS) | успех, `host: extella-team` |
| `24f37e45…` (Мак) | успех, `host: Anvars-MacBook-Pro.local` |

Это подпись H104 — компьютер из чужого аккаунта, а не облачный рантайм: собственный код
аккаунта в облаке исполнился бы. Платформа отправляет вызов без закрепления на машину, где
его исполнить нельзя (письмо Тимуру, §46). Мост рецепта переводит эту подпись в причину
словами; «Экстелла не сообщила устройство, перезапусти» здесь неверно.

**Поправка к собственной ошибке.** Утром 22.09 хранитель канона записал сюда «второй путь —
`parent.extellaDesktop.getDeviceID()`», проверив его на стенде-имитации. В живом окне этот
путь закрыт песочницей. Урок тот же, что H104: **стенд-имитация доказывает логику, но не
окружение** — правило об окружении принимается только после пробы в настоящем окне.

**Проверено в живом окне** (мост рецепта внедрён в настоящий кадр, настоящая платформа):
устройство известно → успех за 9,5 с, вызов закреплён; устройство неизвестно → причина
словами; запомненное устройство исчезло → забыто, один повтор. Охрана:
`templates/app-recipe/tools/check.py` (комментарии не считаются, права, наличие экспертов
в поставке) и `tools/new_product.py --selftest`.
