### H107. УСТРОЙСТВА И ЗАПИСИ О НИХ: КТО ВЫБИРАЕТ МАШИНУ, КОГДА И ЧЕМ ЭТО ЗАДАЁТСЯ

**Замеры 24.09.2026, живой аккаунт, эксперт-пробник `wz_ping` (возвращает имя машины).**
Раздел отвечает на вопрос, который до сих пор решался догадками: почему работа уезжает
не туда.

**Два разных объекта, и путать их дорого.**

* **Устройство** — сама машина. Идентификатор рождается у листенера
  (`~/.extella/device.txt`), виден в строке состояния приложения и в
  `Library → System → Devices`.
* **Запись о цели** (`target`) — именованная ссылка на устройство внутри скоупа:
  `add_target {device_id, description, global}`. Одно устройство может иметь несколько
  записей (у владельца Мак назван тремя: «рабочий листенер», «живой листенер»,
  «устройство покупателя Predictive Sales»).

**В вызовах участвуют идентификаторы УСТРОЙСТВ, а не записей.** Замер: `targets` с
`target_id` записи Мака (`efe19380…`) → `Target efe19380… is unavailable`, хотя машина
включена и работает. Ошибка врёт: это не «недоступна», это «не тот вид идентификатора».

**Как платформа выбирает машину — по путям вызова:**

| Кто зовёт | Чем задаётся машина | Замер |
|---|---|---|
| `run_expert` / `/api/expert/run` с `targets` | список **кандидатов по порядку**, берётся первый доступный | `[VPS, Мак]` → VPS; `[Мак, VPS]` → Мак; `[мёртвый, VPS]` → VPS без ошибки; `[мёртвый]` → `Target … is unavailable` |
| то же **без** `targets` | устройство по умолчанию аккаунта | до смены умолчания → VPS, после смены на Мак → Мак |
| страница продукта через `app-agent/run` без `targets` | **выбор платформы, и он отличался от умолчания**: 22.09 умолчанием был VPS, а вызов ушёл на чужую машину (§46 письма), 24.09 — на Мак | правило выбора платформа не описывает |
| агент, когда сам зовёт эксперта | **закрепить нечем**: у `run_agent` параметра `targets` нет | агент решает сам; отсюда «работает у меня, не работает у коллеги» |

**УМОЛЧАНИЕ — СВОЁ У КАЖДОГО АГЕНТА (замер 25.09.2026, закрывает открытый вопрос H107).**
`/api/defaults/get_target` спрошен с разными `X-Agent-Id` на одном аккаунте:

| агент | его машина по умолчанию |
|---|---|
| `agent_extella_default` | VPS `85800354…` |
| агент Агента 1С (`agent_9Oig…`) | Мак `24f37e45…` |
| агент приложения-гида (`agent_HiSO…`) | Мак `24f37e45…` |

Отсюда объясняется случай §46 письма: вызов страницы без `targets` ушёл не на
устройство «по умолчанию аккаунта», а на умолчание **агента этого приложения** —
тогда им была машина из другого аккаунта. Никакой случайности в выборе не было.

**И умолчание меняется под тобой.** Замер тех же суток: 24.09 умолчание
`agent_extella_default` указывало на Мак (проверено и запросом, и прогоном), 25.09 —
снова на VPS. В аккаунте работает несколько чатов, и каждый может его переключить.
Поэтому правило 3 ниже — не придирка: **продукт, которому нужна конкретная машина,
обязан называть её сам**.

**Области видимости.** Записи скоупятся так же, как эксперты и ключи: `search_targets`
без `global` вернул 3 записи, с `global: true` — 8. Значит часть целей видна только в
скоупе агента, часть — всему аккаунту. **Умолчание задаётся `set_default_target
{device_id}`** — по аккаунту; в интерфейсе `Library → System → Devices → Change default`.

**Правила, которые из этого следуют.**

1. **Закрепляй всегда и массивом.** Одиночное поле `target` установленная витрина читает,
   исходники — нет; канон — `targets: [device_id]` (и `target` строкой рядом, когда
   формат сообщения это допускает).
2. **Список — это резервирование, а не «куда-нибудь».** Порядок значим; первым ставь
   машину, где лежат данные, вторым — запасную, если работа от машины не зависит.
3. **Не полагайся на умолчание.** Оно одно на аккаунт, меняется одним нажатием и разное
   для разных путей вызова. Продукт, которому нужна конкретная машина, обязан её назвать.
4. **Работу агента закрепить нельзя** — если задача обязана исполниться на конкретной
   машине, её выполняет эксперт с `targets`, а не «агент, который сам сходит».
5. **`Target … is unavailable` значит три разных вещи:** машина выключена; передан
   идентификатор записи вместо устройства; устройство удалено. Первым делом сверяй вид
   идентификатора — это бесплатно.
6. **Машина из другого аккаунта отвечает не отказом, а синтаксической ошибкой** — H104.

**Гигиена аккаунта.** Записи накапливаются: у владельца на три живые машины было семь
записей, включая мёртвую (`11b0c773…`, перерегистрирована 30.07) и чужую
(`39f81469…`, листенер в другом аккаунте). Мёртвые записи не безобидны: пока такая
запись жива, платформа может выбрать её для вызова без закрепления. Чистка —
`Library → System → Devices`, меню «…» на карточке (появляется по наведению);
`delete_target` по API сработал не на всякой записи (§49 письма).
