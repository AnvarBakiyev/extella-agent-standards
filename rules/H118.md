### H118. ИНСТРУМЕНТ, КОТОРЫЙ МЫ ВЕЛИМ ЗАПУСТИТЬ, ОБЯЗАН ПЕРЕЖИТЬ УЗКУЮ КОНСОЛЬ

**Замер 28.09.2026, первый в истории прогон CI на `windows-latest`.** Консоль Windows
работает в `cp1252`, и `print("  ✓ H78: источник ключа…")` роняет процесс
`UnicodeEncodeError` на первом же символе. Человек видит стектрейс вместо подсказки,
причём ДО того, как инструмент что-либо сделал. До этого прогона README обещал «любую
ОС», а CI знал только ubuntu: про Windows мы говорили, ни разу её не запустив.

**Норма.** Всякий инструмент, который документ велит запустить человеку, переводит
`stdout` и `stderr` в UTF-8 при старте — шестью строками в точке входа, не падая там,
где поток подменён. Проверяется ПОВЕДЕНИЕМ: гейт запускает самопроверку каждого такого
инструмента в `PYTHONIOENCODING=cp1252` и ловит `UnicodeEncodeError`.

**Список не пишется руками.** Он собирается из документов, которые читает новичок:
README, вход агента, копируемый промпт, онбординг, текст приложения. Скажем завтра
запускать новый инструмент — он попадёт под проверку сам, без нашей памяти.

**Граница названа вслух, а не умолчана.** Печатают по-русски почти все инструменты
репозитория, и на Windows упадёт каждый; гейт печатает это число в каждом прогоне.
Закрыт путь новичка, а не Windows целиком — поддержка Windows этим НЕ объявляется
(открытая часть F04 аудита 28.09.2026).

Держит `tools/check_windows_console.py`.
