### H105. JAVA-ОКНА (NCALayer) ВОДЯТСЯ КЛАВИАТУРОЙ, НЕ МЫШЬЮ. ПАРОЛЬ — ТОЛЬКО ПОСЛЕ ПРОВЕРКИ ОКНА

**Происхождение правила — важно для доверия.** Замеры сделала коллега на своей машине,
объяснение дал чат Агента 1С, **хранитель канона это не воспроизводил**. Чат 1С прямо
оговорил, что своими руками окно не трогал: в Агенте 1С он пошёл другим путём — через
**протокол NCALayer**, а не через интерфейс. Пункты ниже перед внедрением подтверждать
на своей машине.

**Замер (коллега).** Окно NCALayer 1.4 нарисовано на Java (Swing). У такого окна **одно
настоящее окно Windows** — рамка; кнопки и поля внутри рисует Java на холсте, и для системы
их не существует. Отсюда три наблюдения:

* клик по координатам кнопки **промахивается** — координаты берутся из того, чего в системе
  нет, а при масштабе экрана 150 % логические координаты расходятся с физическими в полтора
  раза;
* вызов шаблона UI Automation (`invoke`) **возвращает успех и не делает ничего** — система
  отдаёт заглушку, у которой шаблон формально есть;
* **`Enter` после `set_focus` срабатывает** — клавиатура единственный канал, который честно
  пересекает границу Java: нажатие уходит в окно, дальше его обрабатывает собственная система
  фокуса Java.

**Цена.** Пустые подписи без сообщения об ошибке: автоматика «отработала успешно», документ
не подписан. Молчаливый успех — самый дорогой вид отказа, его не ловит ни один зелёный тест.

**Правило:**

1. **Водить клавиатурой.** Найти окно верхнего уровня, поставить фокус, дальше только `Tab`,
   стрелки, пробел, `Enter`. Никаких координат и никаких шаблонов UI Automation.
2. **Окно дожидаться, а не предполагать.** Java-окна появляются раньше, чем готовы принимать
   ввод: дождаться по устойчивому признаку → пауза → фокус → **убедиться, что окно переднее** →
   только теперь клавиши.
3. **Ветвиться по окну, а не по сценарию.** У NCALayer два вида окна (длинное с паролем и
   короткое «Подписать») — фиксированной последовательности клавиш быть не может. Признак
   различения (заголовок, класс, размер) **замерить у себя**, он версионно-зависим.
4. **Процесс объявляет себя DPI-совместимым**, иначе врут и координаты, и проверки «попали ли
   мы в окно».

**БЕЗУСЛОВНОЕ ТРЕБОВАНИЕ ПРО ПАРОЛЬ — не опция.** Фокус в Windows уводится чем угодно:
уведомлением, антивирусом, другой программой, самим человеком. Если в этот момент робот
печатает пароль от ЭЦП, пароль уходит **в то окно, которое оказалось передним** — в чат,
в документ, в поле поиска — и остаётся там в истории.

Поэтому **непосредственно перед вводом пароля заново получить дескриптор переднего окна и
сравнить с целевым; не совпало — прервать и не печатать ничего.** Проверка обязательна,
отключать её нельзя.

**И архитектурный вывод, который дороже всех четырёх пунктов:** если у внешней программы есть
**протокол**, работать надо по протоколу, а не по её окну. Агент 1С так и сделал и этих поломок
не получил вовсе. Автоматизация чужого интерфейса — последнее средство, а для подписи под
документом её лучше не применять: подпись ставит человек.
