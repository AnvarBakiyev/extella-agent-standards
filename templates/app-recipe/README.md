# Рецепт нового приложения Extella

Это отдельная заготовка. Она не связана с опубликованными приложениями и не меняет их.

## 1. Старт

Копируется папка `app/`: `index.html`, `styles.css`, `extella-bridge.js`, `app.js`. В ней уже есть:

- одна понятная задача на экране, действие и вывод результата;
- карточки, форма, статус, таблица и состояния;
- единый диспетчер запросов к Extella;
- локальный demo-режим: интерфейс можно проверить без эксперта;
- доступные тестовые идентификаторы `data-testid`.

Открыть локально: `python3 -m http.server 8080 --directory app`, затем `http://localhost:8080`.

## 2. Дизайн

Токены лежат в [`app/styles.css`](app/styles.css). Принцип: один тёплый акцент, один системный цвет, мягкая иерархия поверхности, цифры таблично выровнены. Пустое состояние объясняет следующий шаг; ожидание — конкретное действие и отмена; ошибка — причина и повтор; готово — что изменилось и куда смотреть.

Никогда не использую: радужные градиенты, стеклянные панели поверх стеклянных панелей, «плашки ради плашек», десятки цветов статусов, огромные hero-заголовки в рабочем окне, иконки без подписи, бесконечные скролл-карусели, псевдо-ИИ текст вроде «магия уже происходит», случайные проценты/графики и анимации, которые скрывают изменение данных.

## 3. Связь с платформой

Весь обмен собран в [`app/extella-bridge.js`](app/extella-bridge.js): один `ExtellaBridge`, много только явно разрешённых имён экспертов, единый ответ `{ok, data, error}`. Интерфейсный код в [`app/app.js`](app/app.js) про транспорт не знает. Способ снят изнутри живого окна ОС 22.09.2026 и проверен там же (канон H106):

1. ОС подставляет ключ окна в `index.html` на месте `{{app_token}}`. Вне Extella плейсхолдер остаётся как есть, и приложение работает в демо-режиме.
2. Мост сам зовёт `POST https://os.extella.ai/api/app-agent/run` с телом `{app_token, expert_name, params, targets?}`. Протокол `etb_run_expert` и `parent.extellaDesktop` в окне ОС **не работают**: первый никто не слушает, второй закрыт песочницей.
3. Устройство платформа странице не сообщает — его называет **эксперт-диспетчер** приложения (`routeExpert`, образец [`experts/my_app_where.py`](experts/my_app_where.py) читает `~/.extella/device.txt` и отдаёт `pageRoute.targetId`). Первый вызов идёт к нему без `targets`, все следующие мост закрепляет `targets:[device]`. Хранилище в окне запрещено песочницей, поэтому память живёт до закрытия окна.
4. Первый вызов (к диспетчеру) идёт без устройства — машину выбирает платформа. Если она выбрала компьютер, вошедший в другой аккаунт, мост говорит это словами вместо «синтаксической ошибки» (H104).
5. Эксперт сохраняется в агента, от которого публикуется приложение (`--source-agent`), а выкладка просит права `expert.run` **и** `device.run` — второе не входит в первое.

Для задачи длиннее 10 секунд кнопка сразу становится недоступной, рядом появляется «Считаю…», остаётся видимой последняя валидная версия результата, а через 90 секунд пользователь видит честное «не получили подтверждение» и кнопку «Повторить». Не показывать «готово» до подтверждения. Если платформа отложила работу в фон (около 51-й секунды), мост так и говорит — повтор идемпотентного шага через минуту.

## 4. Скорость

Главный выигрыш — не рисовать каждый раз с нуля. Переиспользуются токены, компоненты, мост, build/check и сценарии приёмки. Сначала делаю рабочий локальный расчёт и интерфейс, затем один маршрут Extella, затем экспорт/интеграции. Независимые проверки запускаются параллельно: синтаксис, расчётное ядро, UI-контракт, визуальные снимки.

Обычный путь: 15–25 минут на каркас и реальный сценарий, 20–40 минут на модель/настройки, 15–30 минут на интеграцию и проверку, затем приёмка на чистом устройстве. Это ориентир, не обещание: внешние эксперты и магазин могут добавить ожидание.

Сознательно срезаю: сложные анимации до появления реальных данных, универсальный конструктор форм, вторую дизайн-систему, сетевые зависимости для базового экрана и экспорт до того, как пользователь видит корректный результат.

## 5. Грабли Extella

| Симптом | Правило обхода |
|---|---|
| `Origin: null` | Это штатная песочница страницы. Не обращаться к `parent.extellaDesktop`; использовать scoped `app_token`. |
| `Failed to fetch` / internal address | Не делать `fetch` из страницы к localhost или внутренним IP. Связь с устройством — только через `https://os.extella.ai/api/app-agent/run`. |
| `invalid decimal literal (<container>, line 1)` | Не синтаксис: задание ушло на компьютер из другого аккаунта (H104). Мост переводит это в причину словами. |
| Устройство не определилось | Показать причину словами и оставить повтор доступным. Ручной ввод Device ID — только запасной путь, пока платформа не отдаёт странице устройство (письмо Тимуру, §46); так сделано в Агенте 1С 1.66.0. |
| Истёк ключ | `app_token` живёт два часа; попросить обновить окно Extella. |
| Пустая страница на `/` | В zip должен лежать `index.html` в корне, не в лишней папке. Проверяет `tools/build.py`. |
| Зависший `prompt()` | В интерфейсе не использовать `prompt`, `alert`, `confirm`. Только собственные модальные окна или встроенные поля. |
| Ответ больше 200 КБ | Эксперт возвращает короткий итог, а большие данные записывает в целевое приложение/файл; в панель передаётся ссылка, id или сводка. |
| `async` / Worker ведёт себя нестабильно | Критический путь — обычные async-функции в главном окне. Worker — только необязательное ускорение с синхронным fallback. |

## 6. Проверка у другого человека

Автоматически можно прокликать саму панель: [`tests/smoke.mjs`](tests/smoke.mjs) запускает браузер, меняет ввод, проверяет сценарий, ожидание и ошибку. Для эксперта используется режим `host=mock`, который симулирует ответ Extella. Это ловит регрессии до выкладки.

Но полный путь на другом устройстве нельзя честно считать проверенным только headless-тестом. Минимальная приёмка: чистый профиль/другое устройство → открыть установленное приложение → пройти основной путь → проверить каждую кнопку → один успешный и один ошибочный ответ эксперта → закрыть и открыть снова → проверить, что результат сохранён там, где обещано. В `qa-checklist.md` есть готовый лист.

## 6б. Показать владельцу — с доказательством, а не на словах

Сразу после закрытой выкладки:

```
python3 tools/show.py <listing_id>
```

Скрипт просит стенд открыть приложение **как посторонний покупатель** на живом
`os.extella.ai`, кладёт снимок экрана в `dist/` и говорит обычными словами: открывается
или нет, что с кнопками. Человек видит свою вещь живой и доказательство, что она откроется
у других, — а не фразу «всё готово».

Стенд задаётся `EXTELLA_BENCH_URL` и `EXTELLA_BENCH_KEY` (или `~/.extella_bench.json`).
Стенда нет — скрипт не падает: печатает адрес приложения и как завести стенд одной
командой. Правило целиком — H66 в `DEPLOY_REQUIREMENTS.md`.

## 7. Перед выкладкой

Смотри [`qa-checklist.md`](qa-checklist.md). Сборка: `python3 tools/build.py`; быстрые запреты и структура: `python3 tools/check.py`. Скрипт `tools/deploy_prerelease.py` публикует только закрытый листинг и требует токен из переменной окружения, не хранит секреты в коде.

## 8. Что можно копировать

- [`app/index.html`](app/index.html) — панель целиком;
- [`app/styles.css`](app/styles.css) — палитра и компоненты;
- [`app/extella-bridge.js`](app/extella-bridge.js) — мост, устройство и ожидание;
- [`experts/my_app_where.py`](experts/my_app_where.py) — диспетчер устройства; [`experts/my_app_expert.py`](experts/my_app_expert.py) — образец рабочего эксперта;
- [`app/app.js`](app/app.js) — пример сценариев, состояний и локального fallback;
- [`tools/build.py`](tools/build.py), [`tools/check.py`](tools/check.py), [`tools/deploy_prerelease.py`](tools/deploy_prerelease.py) — сборка, проверки и закрытая выкладка;
- [`tests/smoke.mjs`](tests/smoke.mjs) — автоматический smoke-test.
