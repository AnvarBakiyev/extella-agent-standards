# Издание за день

Издание — это **не новая ОС**, а набор из четырёх частей, которые платформа уже умеет:
тема оформления, набор приложений, отдел агентов и полка в магазине по тегу.
Доработок платформы не требуется — проверено замерами 13–14.08.2026.

Порядок ровно такой. Первые два шага — половина успеха; их обычно и пропускают.

## 1. Придумать (час, без кода)

Заполни `edition.yaml`: **для кого** и **почему он бросит то, чем пользуется сейчас**.
Гейт не пропустит пустые поля намеренно: издание, которое не описывается двумя
предложениями, не описывается и продуктом.

**Контекст — жизненная ситуация, а не пол и не профессия вообще.** «Беременность»,
«уход за пожилым родителем», «фриланс с пятью проектами» — продают. «Для женщин» —
это розовая тема поверх того же приложения, и это чувствуется.

## 2. Решить, где живут данные (пять минут, решает всё)

Здоровье, цикл, диагнозы, документы клиента — **только `где_живут: устройство`**.
Гейт роняет сборку, если объявлено иначе.

Это не ограничение, а главный аргумент продажи: облачные конкуренты так сказать
не могут, а мы можем и докажем — эксперт исполняется на машине, наружу уходит
только то, что человек и так видит на экране.

## 3. Собрать

```bash
python3 tools/check_edition.py templates/edition     # до сборки, а не после
```

* **тема** — `theme.js`. Расширение подмешивается во **все** окна ОС, поэтому тема
  обязана первым делом понять, где оказалась, и в чужих окнах молчать. Гейт проверяет
  это по коду, а не по обещанию;
* **приложение** — страница по образцу `store_app/` (текст в `content.json`, правится
  коммитом без перевыпуска). Одно приложение, которое делает одно дело целиком,
  лучше трёх наполовину;
* **отдел** — профиль из нескольких агентов одним листингом. Форма принята платформой,
  но **пустой отдел публикуется без возражений** — состав проверяй сам.

## 3б. Состав издания, если это набор

Издание — не оформление, а **готовое рабочее место под роль**. Что входит, перечисляется
в `compose.yaml`: наши приложения, агенты, скиллы ассистента, подключения MCP, инструменты
командной строки, репозитории, модели.

```bash
python3 tools/check_compose.py editions/твоё      # состав честен?
python3 editions/твоё/install_edition.py --план   # что поставится, ничего не делая
```

Гейт состава ловит то, что всплывёт только у покупателя: репозиторий по плавающей ветке,
правка конфига ассистента без копии, секрет в архиве, установку дольше пятнадцати минут,
модель на гигабайты без согласия и отсутствие обещания «снимается полностью».

**Установщик обязан уметь снимать.** У нас уже был случай, когда поставленное нечем было
убрать — это плохая история, а не мелочь. Поэтому каждый шаг пишется в расписку, и
`--снять` идёт по ней.

## 4. Выпустить — одной командой

```bash
python3 tools/deploy_edition.py editions/твоё --сухой   # сначала посмотреть план
python3 tools/deploy_edition.py editions/твоё           # весь путь
```

Скрипт делает всё сам: гоняет гейт, заводит агента издания **по API** (человек не нужен —
замер 14.08.2026), пишет экспертов в его скоуп и **сверяет посимвольно**, выкладывает
предрелизом, покупает тебе и принимает чтением состояния.

Три ловушки он снимает за тебя, и каждая уже стоила кому-то дня:

* **есть листинг — добавляется ВЕРСИЯ, а не новый листинг.** `publish-stream` каждый раз
  создаёт новый: так на аккаунте завелось три Predictive Sales с тремя агентами;
* **оборванный поток не считается успехом** — иначе повтор создаст дубль;
* **приёмка читает состояние**, а не верит ответам на запись.

Останавливается перед `Publish`: эту кнопку жмёт человек.

Права (`app_scopes`) — **минимум**. Пусто = продукт откроется целым и не заработает,
каждый вызов вернёт `403`. Покупатель видит список прав до покупки.

## 5. Сдать

Отчёт тремя частями: **закрыл / не моё / не закрыл честно.** Названный незакрытый
пункт полезнее зелёных галочек.

---

**Мера успеха — не количество изданий, а время сборки одного.** Два дня — конвейер
работает, можно масштабировать. Две недели — чинить конвейер, а не набирать людей.
