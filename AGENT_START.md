# Старт для агента: одна страница, дальше по адресам

Ты подключаешь человека к Extella и строишь на ней. Эта страница — вход. Она
маленькая намеренно: всё остальное берётся **по одному файлу**, а не целиком.

## Правило чтения (из-за него провалились первые внешние агенты)

**Бери сырые ссылки, а не страницы GitHub.** Замер 25.09.2026: страница репозитория —
497 КБ оформления, сырой README — 31 КБ. Свод правил `DEPLOY_REQUIREMENTS.md` — 369 КБ:
веб-чтение его обрезает, и до правил агент не доезжает. Поэтому правила разложены
по одному на файл, по 2–11 КБ:

    https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/H106.md

Оглавление всех 116 правил (9 КБ): `rules/INDEX.md`.

**`extella.ai/api.html` — не источник правды.** Это публичная справка, она неполна:
рабочие пути (вызов эксперта со страницы, публикация, закрепление за машиной) в ней
не описаны. Молчание справки ничего не доказывает. Источник — этот репозиторий.

## Десять ловушек, на которых встают все

1. **Ключ один, заголовки разные.** Магазину (`os.extella.ai`) — `X-Extella-Token`,
   ядру (`api.extella.ai`) — `X-Auth-Token`. Особый файл не нужен: годится любой
   действующий ключ аккаунта. → `rules/H109.md`
2. **Ключ на новой машине не появляется сам.** Приложение не кладёт его на диск.
   Человек создаёт ключ в `Library → System → Tokens`, либо подключение делает
   эксперт `dev_connect_assistant`. → `rules/H108.md`
3. **Окно ОС не слушает `etb_*` и не сообщает устройство.** Страница зовёт
   `POST os.extella.ai/api/app-agent/run` с `{{app_token}}`. → `rules/H106.md`
4. **Устройство называет эксперт-диспетчер**, дальше все вызовы закрепляются
   `targets: [device_id]`. Прогон агента закрепить нечем. → `rules/H107.md`
5. **Права приложения выдаются отдельно.** `403` означает «не разрешено», лечится
   в карточке приложения, а не в коде.
6. **Отложенный прогон — не ошибка.** Платформа откладывает работу примерно на
   51-й секунде: «выполняется» ≠ результат, состояние читается отдельным лёгким
   экспертом. → `rules/H54.md`
7. **Лимиты канала:** тело запроса до 64 КБ, ответ держать меньше 200 КБ, до 30
   вызовов в минуту. Файлы читает эксперт на устройстве, а не браузер.
8. **Ответ приходит в двух обёртках**, и словарь Python — не JSON. → `rules/H17.md`
9. **`invalid decimal literal (<container>, line 1)`** — не синтаксис: код не
   расшифровался на устройстве, ключ не совпал. → `rules/H104.md`
10. **Агент, созданный по API, не разговаривает** (`agent/run` → 400): диалоговый
    агент создаётся человеком в интерфейсе. Эксперты при этом работают.

## Первые действия

```
python3 tools/connect_mcp.py          # подключение; если ключа нет — назовёт одно действие
python3 tools/stage_gates.py --stage build --json   # сколько проверок нужно этой работе
```

На Windows `python3` может называться `py -3`. Если инструкция не сработала —
это факт для нас: пришли дословный вывод, мы поправим канон.

## Чем доказывается, что ты прочитал

Прежде чем строить, назови **номера правил своей задачи и по одной строке на каждое**
из таблицы выше. Это дешевле, чем четыре дня переписки: первые внешние агенты
объявляли «платформа не умеет» там, где правило было написано и замерено.

## Как спорить с каноном

Если замер противоречит правилу — приводи дословный ответ платформы: какой вызов,
какие заголовки, какой код. Канон правится по замерам, и половина правил здесь
появилась именно так. Гипотезы без замера в канон не попадают.
