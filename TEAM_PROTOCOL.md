## Железные правила

1. **Один клапан наружу.** main, подписанный релиз, пин SHA в install-all, всё на VPS — двигает ТОЛЬКО интегратор. Сдача работы = ветка + отчёт (симптом/причина/файлы/гейты/откат).
2. **Дев-сессии работают ТОЛЬКО в git worktree/ветке** (`.claude/worktrees/...` или ветка от свежего origin/main). В общем клоне не редактирует никто, кроме интегратора. Незакоммиченное в общем клоне = инцидент.
3. **Объявляй работу.** Перед стартом задачи — строка в `docs/WORKBOARD.md` (задача · сессия · ветка · статус). Закончил/сдал — обнови строку. Интегратор чистит доску.
4. **Правило файла (№8).** Один файл — один владелец правки одновременно. Перед правкой: `git fetch` + взгляд на WORKBOARD; коллизия → второй ждёт коммита первого.
5. **Гейты обязательны** перед сдачей: `preflight_ui.sh` («ВСЁ ЧИСТО»), `smoke_e2e.py` (все зелёные), для движка — живой `live_wizard_agentic_e2e.py` зелёный ДВАЖДЫ ПОДРЯД.
6. **Канон платформы** (EXTELLA_AI_ONBOARDING.md, CLAUDE.md репо): клиентские агенты только Qwen; секреты не печатать; «not found» платформа шлёт как HTTP 500 — это «пусто», не потеря связи; 5xx/timeout ≠ провал (ретрай); немой отказ = дефект — причина обязана доезжать словами.
7. **Приватный код не публикуется на GitHub** — раздача zip'ом с files.82-115-42-21.sslip.io (секрет-скан обязателен).
8. **Коллеги — не тестировщики.** Воспроизводим на тест-аккаунте (~/.extella_test_token) и артефактами; коллегу дёргаем максимум одной финальной командой обновления.
9. **Codex-координация** — через handoff-файлы в репо (docs/CODEX_*.md): репро, причина, направление, критерий приёмки. Claude-сессии между собой — межсессионными сообщениями с обязательным ответом-отчётом.
10. **Деплой оверрайда тулбара — ТОЛЬКО из origin/main.** Файл `~/Library/Application Support/extella-desktop/toolbar.js` кладётся исключительно через пак/RAW/install-all (= origin/main). Прямой деплой из бокового клона или worktree ЗАПРЕЩЁН: 24.07 боковая сборка Эллы (ветка до 23.07, без main-фиксов) перетёрла рабочий оверрайд напрямую в ~22:22 → витрина печатала сырой JSON. У кого есть свой клон тулбара — пересобирает и деплоит ТОЛЬКО из свежего origin/main, своя работа туда уже влита. Диагностика при «витрина сломалась»: ПЕРВЫМ делом `grep -c hasSnapshot;grep -c onlyKnown` на задеплоенном toolbar.js vs пак — рассинхрон версий вероятнее регрессии кода.
11. **Релизный артефакт тулбара собирается ТОЛЬКО из чистого клона origin/main**, не из локального worktree с ассетами. 25.07 интегратор собрал Студию из Codex-worktree со СТАРЫМ `profit-growth.html` → артефакт разошёлся с каноном (лишние незаэкранированные `</script>` — класс инцидента витрины). Правильно: свежий клон `git clone`/`git checkout origin/main` в чистой директории → `node toolbar/build.js --release-artifacts` → сверить sentinels + `grep -c '^</script>'`=0 → деплой. Локальные worktree дев-сессий как источник сборки запрещены.

## Что присылать в общий контур, а что делать самому

**Правило появилось 17.08.2026** после сообщения, в котором на **один новый факт**
пришлось десять строк процесса: «сохраняю в память», «жду переподключения», «сейчас
проверю». Факт был ценный — токен в окружении эксперта есть не на каждой машине. Всё
остальное было отчётом о шагах, который читающему не нужен.

**Порог простой: присылай результат, а не шаг.**

| присылай | не присылай |
|---|---|
| **дефект**, который воспроизводится: что делал, что ожидал, что вышло, на какой машине | промежуточные шаги отладки |
| **лучшую практику**: что заработало и стоит записать другим | «сохраняю», «жду», «сейчас проверю» |
| **развилку**: два пути, и выбор меняет продукт | просьбу подтвердить очевидное |
| **опровержение канона**: правило не сработало — это самое ценное | пересказ того, что уже есть в каноне |

**Сначала загляни в канон.** `DEPLOY_REQUIREMENTS.md` — всё, что мы измерили о
платформе; `LAB.md` — что пробовали и почему закрыли. Половина вопросов там уже
отвечена замером, а не мнением.

**Час на самостоятельный поиск.** Не вышло — пиши, но сразу с тем, что уже проверил
и что исключил: это превращает твоё сообщение из вопроса в половину решения.

**И обратное правило для нас.** Рецепт, проверенный на одной машине, выдавать как
универсальный нельзя. Именно так я и подвёл коллегу в тот же день: механизм чтения
секрета работал у владельца и не работал у неё, а в ответе этого различия не было.
