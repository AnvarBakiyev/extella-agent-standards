# Промпт «обнови продукт под стандарты» — раздаточная версия

Канонический текст для раздачи чатам-строителям. Версия 2, 12.08.2026 — после калибровки
на четырёх живых сессиях (Console, Баға, Travel, Privacy Gateway). Раздавать отсюда,
не по памяти: правки вносятся в этот файл.

---

**Обнови своего агента/продукт под стандарты Extella (редакция 12.08.2026).**

**Правило №0: работай только в namespace своего продукта.** Аккаунт общий; чужие
эксперты, правила, агенты коллег и владельца не трогать вовсе. Удаление вне своего
namespace — только после подтверждения человеком, и даже тогда: потребители до
(кто зовёт имена — grep по репозиториям и карточкам), смоук потребителей после.

Прочитай перед работой (репозиторий: github.com/AnvarBakiyev/extella-agent-standards,
склонируй или обнови — локальная копия может отставать):

- `START_HERE.md` — с чего начать;
- `BUILD_STAGES.md` — стадии, стоп-правила и правила поведения чата;
- `DEPLOY_REQUIREMENTS.md` — типы по каналу доставки (вопрос №0 — четыре вопроса
  в начале), разделы A–H, приёмка перед Publish.

**Порядок работы:**

1. **Определи канал доставки** (вопрос №0 первым): витрина-страница / витрина-архив /
   встроенный компонент. Встроенному компоненту витринные требования не нужны —
   не заводи их.
2. **Объяви стадию и факты**, объём возьми у машины:
   `python3 tools/stage_gates.py --stage build --json`. Гейты с пометкой «аккаунтный» —
   не твои: назови их в отчёте и отдай интегратору. Стадию не объявил — считается prod.
3. **Меняй поведение, а не производи документы.** Новые контракты/манифесты «на всякий
   случай» не заводить; чего не хватает — строка в отчёте.
4. **Работай в рабочей копии, результат — ветка в origin.** Не в temp-клоне.
5. **Свой агент:** проверь, что думает (`agent/run`, `agent_id` в теле); роль файлом в
   репо → прошивка целиком → путь отката; **сузь инструменты** — свежий агент рождается
   с `sys__all__` и `delete_*`, это обязательный шаг. Живой интерфейс Extella не водить:
   создание агента в UI — действие человека, попроси владельца.
6. **Экспертов пиши через REST** (`POST /api/expert/save` + `X-Agent-Id`), не через MCP
   `save_expert`. После записи перечитай и сравни по содержимому (поле `expert_code`).
   **Проверь саму сверку**: сломай нарочно одно поле и убедись, что она падает.
7. **Канонические общие модули** (`platform_client`, экран выбора) на месте не править —
   правка в канон, копии синхронизацией.
8. **Завершение:** готовый zip в названном месте + инструкция. Инструкция ведёт в
   **предрелиз**, не в Publish: перед публикацией обязательна приёмка — предрелиз →
   покупка себе → первый запуск чистым состоянием (без конфигов владельца). Клиентские
   ключи (Tourvisor, WhatsApp, CRM) — не блокер: продукт без них обязан быть честным
   (онбординг просит ключ, «не подключено» словами). Кнопку жмёт человек.

**Стоп-правила (нарушение = брак на любой стадии):** внешняя запись только черновиком;
данные клиента только в контуре клиента; без `delete_*` у клиентского агента; чужое
живое не трогать; секреты не едут в архив; отказ виден словами.

**Отчёт — три части: «закрыл / не моё / не закрыл честно»**, плюс OWNER_TASKS.md с
точными шагами для человека, если они есть. Честно названный незакрытый пункт полезнее
зелёных галочек.
