# Стол ОС: плитка ≠ покупка

Замер 20.08.2026 на «Пульте CEO» (шесть панелей): покупки на сервере идеальные,
но три плитки из шести на столе не появились — одинаково в браузере и в
приложении. Разбор кода стола (desktop.js осевой сборки) дал механику, которой
не было ни в одном нашем документе. Исполняемый источник — `tools/ярлык_на_стол.py`;
при расхождении текста и кода прав код.

## Главное

**Программная установка создаёт ПОКУПКУ, но НЕ плитку.** Плитки стола рисуются
из отдельного серверного состояния — `/api/desktop-state` (хост ОС, заголовок
X-Extella-Token). Покупка через `purchase-stream` / `переустановить()` в это
состояние ничего не добавляет: приложение куплено, открывается прямым адресом,
а на столе его нет. Дефект осевой сборки заявлен техотделу; до починки ярлык
ставит наш инструмент.

## Устройство состояния стола

`GET /api/desktop-state` → `{state, rev}`. Слои `state`:

| слой | что хранит |
|---|---|
| `pos` | позиции плиток `{id: {x, y, f}}` (`f` — id папки) |
| `folders` | папки стола |
| `appShortcuts` | ярлыки-«приложения» `{sid: {lid, name}}`. ЛОВУШКА: без агента такой ярлык открывает КАРТОЧКУ МАГАЗИНА, а не приложение (замер 20.08.2026) — для страничных продуктов не годится |
| `shortcuts` | **прямые ссылки `{sid: {name, url}}` — ПРАВИЛЬНЫЙ тип плитки приложения**: url `https://os.extella.ai/app-page/{lид}/` (со слэшем) открывает окно сразу, иконка листинга и бейдж ↗ подставляются сами |
| `links` | файлы/папки устройства |
| `trash` | корзина (id плиток) |
| `vers` | закреплённые версии приложений |

Запись: `POST /api/desktop-state` с телом `{state}` — состояние целиком.
Открытые столы подтягивают чужие правки сами (поллинг ревизии), перезапуск не
нужен.

## Правила (кровью)

1. **Бэкап перед любой записью.** POST пишет состояние целиком: криво собранный
   `state` — это снесённый стол человека. Инструмент кладёт полную копию в
   `~/extella-cabinet/записи/desktop_state_бэкап_<время>.json` до записи.
2. **Только добавлять.** Читаем живое состояние, добавляем свои записи, чужие
   слои не трогаем. Никаких «пересобрать заново».
3. **Идемпотентность.** Ярлык с тем же `lid` уже есть — не дублировать.
4. **Гонка с открытым столом**: его клиент сохраняет своё состояние с задержкой
   400 мс; наша правка между его правками может быть перекрыта. После записи —
   перечитать и убедиться, что ярлык на месте.

## Как поставить плитку

    python3 tools/ярлык_на_стол.py <listing_id> --имя "CEO · Маркетинг" [--x 900 --y 300]

Без `--x/--y` стол сам найдёт свободное место при следующей загрузке.
