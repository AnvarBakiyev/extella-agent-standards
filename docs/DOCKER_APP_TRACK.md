# Docker-трек: серверное приложение → контейнер → окно ОС

Проложен 20.08.2026 на Uptime Kuma («Сторож»). Всё ниже — замеры, не мнения.
Исполняемый источник — `tools/install_docker_app.py` и `tools/cabinet_server.py`
(прокси-режим); при расхождении текста и кода прав код.

## Зачем трек

Добыча спроса 19.08.2026: по звёздной массе ≈65% желанных приложений — серверный
docker-класс (Immich 112k⭐, n8n 201k, Vaultwarden 66k, Stirling-PDF 90k, Jellyfin 56k),
браузерная статика — ≈6%. Браузерный конвейер ловит хвост спроса, этот трек — голову.

## Как поставить приложение

    python3 tools/install_docker_app.py \
        --образ louislam/uptime-kuma:1 --slug uptime-kuma --имя "Сторож" \
        --порт-внутри 3001 --том /app/data \
        --лицензия https://raw.githubusercontent.com/louislam/uptime-kuma/master/LICENSE \
        --глиф activity

Шаги установщика: докер жив → compose и контейнер (на внутреннем порту) →
прокси с шимом наружу → проба перезапуском → лицензия → плитка Bronze
Engraved, карточка, окно. Дальше руками: заполнить listing.json, выложить
предрелизом, Publish — владелец. Предрелиз — это версия продукта, которую видит
только автор.

## Правила трека — каждое закреплено самопроверкой

- **Порт только 127.0.0.1.** Контейнер на 0.0.0.0 раздаёт приложение всем
  соседям по сети — у чужого ноутбука в том же кафе появляется ваш сторож.
- **Данные — томом в `~/extella-cabinet/docker/<slug>/данные`**: видны файлами,
  бэкапятся, переживают пересоздание контейнера.
- **Перезапуск — шаг установки, а не обещание.** Контейнер перезапускается и
  обязан ответить снова, иначе установка не состоялась.
- **`restart: unless-stopped`** — переживает ребут вместе с Docker Desktop;
  LaunchAgent контейнеру не нужен (прокси — нужен, его ставит установщик).
  Docker Desktop должен стартовать при входе — проверить галку в его настройках.
- **Первичный пароль задаёт владелец.** Агент не заводит аккаунты и не выбирает
  пароли даже в локальном контейнере.
- **Беспарольный локальный контур — по слову владельца** (решение Анвара
  21.08.2026: «вход уже охраняет Extella»). Два штатных пути: выключить auth
  самого приложения (Kuma: setting `disableAuth`) или автовход прокси —
  `cabinet_server --автовход <json {путь, тело}>`: при 401 прокси входит сам
  машинным секретом (файл 600 рядом с .env, человеку не показывается) и
  повторяет запрос; сессию держит банка кук. Порт при этом ТОЛЬКО 127.0.0.1 —
  беспарольность не выходит за пределы компьютера.
- **Вход бывает не кукой.** Замеры 21.08.2026 на Memos: (1) токен приезжает
  ПОЛЕМ ТЕЛА ответа (`accessToken`), а не Set-Cookie — конфиг `"кука_из_тела":
  {"поле": "accessToken", "как": "bearer"}` кладёт его в банку спец-ключом, и
  прокси шлёт `Authorization: Bearer` (кука с тем же токеном даёт 401, Bearer —
  200); (2) refresh-куку приложение ставит служебным заголовком
  **`Grpc-Metadata-Set-Cookie`** (обычный путь connect-rpc) — сборщик по имени
  «Set-Cookie» её не видит, и окно показывает форму логина при живом токене.
  Прокси собирает оба заголовка и на входе, и на каждом проксируемом ответе:
  без второго сессия ломается в середине работы при ротации токена.

## Песочница окна ОС: полный список дверей (кровью)

Окно ОС — песочница без адреса (`Origin: null`). Для докер-класса страницы
отдаёт контейнер, в файлы шим не вставить — поэтому **наружу смотрит прокси**,
который вшивает шим на лету. Всё, что убивало окно, по порядку обнаружения:

| Дверь | Как выглядит | Лечение |
|---|---|---|
| localStorage / sessionStorage | молча теряет работу | шим: хранилище → файл на диске |
| document.cookie | бросает SecurityError | шим: cookie-банка в памяти |
| IndexedDB | «вежливый отказ» вешал localforage вечным Loading | шим: `indexedDB = undefined` — «баз нет», это умеют все. Побочный шум: сборки, зовущие `indexedDB.open` без проверки, бросают TypeError «reading 'open'» — докладчик шима не считает это сбоем (замер 20.08.2026, Доска работала, полоска её хоронила) |
| **History API** | `replaceState` бросает; роутер SPA умирает в цикле — белое окно | шим: пробуем родной, отказ глотаем |
| **X-Frame-Options** | контейнер шлёт SAMEORIGIN; браузер скачивает документ и МОЛЧА не рисует его во вложении — белое окно без ошибок и без запросов за скриптами | прокси снимает XFO (и CSP) |
| **Шестая: Cross-Origin-* + сетевые куки** (21.08.2026, tududi/helmet) | `Cross-Origin-Resource-Policy: same-origin` душит В ПЕСОЧНИЦЕ каждый скрипт и fetch (происхождение окна — null, всё «кросс»): в обычной вкладке приложение живо, в окне ОС — белое. Плюс песочница режет сетевые куки — сессия логина не живёт. И дубль ACAO ломает CORS целиком | прокси снимает семейство Cross-Origin-* и Set-Cookie (куки держит банка прокси в памяти, доклеивает в запросы), предполёт проксируемых путей отвечает сам; ACAO шлёт ТОЛЬКО end_headers — один раз |
| **Седьмая: navigator.serviceWorker** (21.08.2026, tududi) | само ЧТЕНИЕ свойства бросает SecurityError — загрузчик умирает до дела; настоящая причина видна только после crossorigin-пометки скриптов прокси (иначе пустое «Script error.») | шим удаляет свойство («воркеров нет»), не даёт браузер — тихая заглушка |

**«Открыть отдельным окном» в Электроне — легенда**: новое окно наследует ту же
песочницу. Запасного пути нет, есть только починенное основное.

## Прокси-режим cabinet_server

    python3 cabinet_server.py --папка <любая> --порт 34788 --имя <slug> \
        --данные ~/extella-cabinet/данные --прокси-на 44788 \
        --шим ~/extella-cabinet/storage_shim.html

Всё, кроме служебных путей (`/_extella_storage|_version|_action`), проксируется
на внутренний порт; в `text/html` вшивается шим. Снимаются: CSP (зарезал бы наш
встроенный скрипт), X-Frame-Options (см. таблицу), сжатие (шим в gzip не
вставить). Сокеты (socket.io) живут длинным опросом через прокси — WebSocket
наш сервер не умеет, и это оказалось не нужно.

## Как диагностировать белое окно (метод трёх раундов)

1. **Журнал охоты**: включить лог запросов на прокси, попросить владельца
   обновить окно один раз. Запросов нет — не доходит; HTML есть, ассетов нет —
   документ не рендерится (ищите XFO/CSP); всё есть — умирает скрипт.
2. **Репродуктор**: страница приложения + замки песочницы (бросающие
   localStorage/cookie/IDB/History) открывается там, где видна консоль.
   Помнить: XFO в репродукторе НЕ виден — он бьёт только вложение.
3. Чинить только по факту из консоли или журнала. Три двери из пяти были
   найдены именно так; ни одна догадка «по памяти» не подтвердилась.

## Контейнер смотрит на мир из своей норы

У контейнера СВОЙ 127.0.0.1 — это он сам, а не Мак. Монитор локальной службы
по адресу `http://127.0.0.1:34786` отвечает «ECONNREFUSED» (замер 20.08.2026,
первый же монитор владельца). Дорога из контейнера к службам Мака — имя
`host.docker.internal`: проверено изнутри контейнера, службы на 127.0.0.1 Мака
по нему отвечают. Внешние адреса (https://…) работают как обычно.

## Приёмка

Установка состоялась, когда: контейнер отвечает после перезапуска · данные
лежат файлами в томе · порт не торчит наружу · плитка и карточка на витрине ·
**владелец видит интерфейс во вложенном окне ОС и проходит первичную настройку
сам**. Сторож прошёл всё 20.08.2026.
