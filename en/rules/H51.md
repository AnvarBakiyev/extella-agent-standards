# H51. The purchase finished, and nothing landed on the device

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H51. The purchase finished, and nothing landed on the device

**Probes from the hybrid-product chat, 12 Aug 2026 and again 17 Aug 2026.**

The purchase reports completion, the page opens — but the product's local part isn't on
the machine: no data, no keychain entry, no state file. From the outside this looks like
an empty or broken product, and people start troubleshooting the interface, not the
install.

**What to do.** Do not treat completion of the purchase as a fact of installation.
Afterward, verify that the archive arrived and unpacked, and tell apart two refusals in
words: there is no archive, versus there is an archive but the install didn't go through.
Both refusals need a visible next step — reinstall from the desktop.

**The second half of the same refusal: there is nothing to pin the device to.** The
shell sometimes fails to pass the agent id to the installer, and the binding is not
created. Before an explicit message appeared, this looked like "it installed, but the
app doesn't see its own files." The installer must refuse BEFORE writing state if the id
was not passed, and re-read the device binding after the install. A half-finished state
is worse than an honest refusal: afterward there is nothing to tell it apart from a
correct one.

**A related case, from the same source.** Falling back to the account's shared agent
instead of the product's own was removed entirely, not fixed: the product's agent is
read only from the local binding, there is no fallback path. A fallback path here is not
a safety net — it's a way to silently do the work in someone else's scope (see H41).
