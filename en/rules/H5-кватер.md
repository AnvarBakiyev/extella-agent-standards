# H5-quater. Asymmetry between the `expert/save` and `expert/get` fields

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H5-quater. Asymmetry between the `expert/save` and `expert/get` fields

`POST /api/expert/save` expects **`name` / `description` / `code`**; `POST
/api/expert/get` takes `name`, and returns the code in the field **`expert_code`**.

**`description` is required: without it `expert/save` answers `422`** (reported by the
Recruiter chat on 13 Aug 2026, this was not in our REST canon before). The refusal looks
like a problem with the expert's code, when the actual issue is a missing description —
and the first thing people do is rewrite the code.

You write under one name — you read under another. A check written on intuition reads
`code`, gets emptiness, and is **always green**: it will never see the discrepancy. This
exact class of defect is the one one of the chats caught in its own check. Hence: compare
**by content**, and make sure the check is able to fail.

**Full contents of the `expert/get` response (captured live on 12 Aug 2026):** `status`,
`expert_name`, `expert_description`, `expert_code`, `expert_prompt`, `expert_params`,
`cspl`, `group_name`, `createdAt`, `updatedAt`, and **`global`**.

Hence two corrections to what the chats had considered a platform limitation:

* **`global` is present in the response** — the scope is verified by reading it, there's
  no need to invent workarounds;
* **there is also a second, independent signal:** the same `expert/get` called on behalf
  of **another** agent answers `Expert not found`. Two different ways to tell the scope
  apart, instead of "indistinguishable."

And a trap in reading this field: `global: true` **does not mean "visible to all
agents."** A live example — an expert with `global = True` that two other agents don't
find at all. The field states a property of the record, and visibility is decided by the
scope (see the canon on shadow scopes). Verify availability by name for a specific
agent, not by the value of the flag.
