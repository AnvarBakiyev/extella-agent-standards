# H65. The app page is cached — the cure has to live in the page itself

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H65. The app page is cached — the cure has to live in the page itself

The platform serves `/app-page/{lid}/` **without a single caching header**: no
`Cache-Control`, no `ETag`, no `Last-Modified` (probe on 24 Aug 2026, live listing).
What to do with such a page is up to each browser, so a product update reaches the buyer
only some of the time, and differently on different computers.

**Releasing a new version by itself does NOT fix delivery.** The window's address does
not change, the browser takes the same copy, and the buyer sees the old one again.
Publishing is still necessary, but treating publishing as the delivery mechanism is a
mistake.

The fix lives inside the page itself and has been verified in production since
21 Aug 2026 (found by a colleague's test on a listing updated three times): the page
carries a version stamp, on startup fetches itself past the cache, checks the stamp,
and, if it has diverged, reloads with a cache-busting parameter.

```js
async function healStaleCache() {
  const response = await fetch(window.location.pathname, { cache: "no-store" });
  if (!response.ok) return false;
  const fresh = await response.text();
  const match = fresh.match(/const PANEL_VERSION = "([^"]+)"/);
  if (match && match[1] && match[1] !== PANEL_VERSION) {
    window.location.replace(window.location.pathname + "?fresh=" + Date.now()
      + window.location.hash);
    return true;
  }
  return false;
}
// вызывать ПЕРВЫМ делом при запуске; если вернуло true — дальше не идти
```

**A limit of the fix that must be understood up front:** the self-heal will only reach
those who have already opened the version that has it. Whoever's copy stuck before that
will not get it, until the browser refreshes the page on its own. Hence the rule: put
the fix into the product **as early as possible**, not once an update is already needed.

For those already stuck, a one-time visit to the address with a parameter (`?fresh=1`)
helps — verified, it returns 200 and lands in a separate cache entry.

The platform still needs `Cache-Control: no-store` on the wrapper regardless:
self-healing costs one extra request on every open and does not save copies that are
already stuck. This item has been logged for the platform team.
