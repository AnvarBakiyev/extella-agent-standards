### H26. PUBLICATION IS REVERSIBLE, DELETION IS NOT. An amendment to what I repeated all day

**Verified on 16 Aug 2026 on the owner's hint.** We treated `Publish` as the point of no
return and built the rule "the chat stops, the person presses the button" on that. Half
of that rule turned out to be wrong.

| action | endpoint | reversible |
|---|---|---|
| show in the store | `POST /api/listing/{id}/publish` `{"published": true}` | **yes** |
| remove from the storefront | same endpoint, `{"published": false}` | **yes** |
| delete the listing | `DELETE /api/listing/{id}` | **NO**: wipes out the listing and ALL versions |

There is no separate `unpublish` endpoint — it's the same `publish` with a flag (read
from `store.js`: the "Unpublish" button calls `setPub(id, 0)`). You can check whether an
endpoint exists without changing anything: a `GET` on it returns `405` if the endpoint
exists, and `404` if it doesn't.

**What changes in practice.** `Publish` remains a PUBLIC action and remains the owner's
call — but not because it's irreversible, it's because everyone can see it. The cost of a
mistake dropped from "forever" to "a minute on the storefront"; fear of the button is no
longer justified. Tool: `tools/set_published.py <id> --show|--hide` — with mandatory
verification by reading back, because "success" without a re-read has already cost us
trust.

**What did NOT change.** H20 still holds: for a published listing, every new version
goes to the store immediately. And deletion is still irreversible — the tool does not do
it on its own.
