# H110. A BAN LIVING INSIDE ONE FILE'S SELF-CHECK DOESN'T CLOSE THE REPOSITORY

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H110. A BAN LIVING INSIDE ONE FILE'S SELF-CHECK DOESN'T CLOSE THE REPOSITORY

**Measurement, 24 Sep 2026, a continuation of H108.** The wrong advice "open the app — the key
will appear on its own" was banned by the self-check in `tools/connect_mcp.py`: it fails if this
text shows up again **in its own refusal**. The ban was considered closed. A repository-wide
search found the same advice in three more places that a person actually sees: the rollout
refusal in `store_app/update.py`, both manifest templates in `tools/new_product.py` (meaning it
got copied into **every new product**), and the "was — became" table in `INSTALLER_CANON.md`,
where the wrong phrase sat in the "became" column — as a model to follow.

Separately: the single entry point `README.md` carried the same promise, because the H108 edit
never touched it. The "one source" rule guards against a second entry point, but not against the
one entry point going stale.

**Rule.** A ban on text is a search across the entire repository, not a check on a single line.
Implemented in `tools/check_assistant_onboarding.py`: the promise is searched for across all
`.md/.py/.json/.html/.txt/.sh` files, narrowed by words about the key (otherwise a truthful line
about the agent coming up unattended after a deploy would give a false hit), and **allowed only
next to a refutation** — the wrong advice may be quoted only where it is stated to be wrong. The
gate skips its own file: the samples themselves live there.

**Check the same way** for any rule phrased as "we no longer write it this way": until it has a
tree-wide search, it's closed in a single file.
