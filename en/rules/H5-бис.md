### H5-bis. A page REACHES THE DEVICE — measured 12 Aug 2026

The most important probe: can a store page run an expert that executes **on the user's
own computer**, rather than in the cloud. On this depended whether products with local
data (1C, files, services) could move into the storefront.

**Answer: yes, it can.**

| Call from the page | Result | Time |
|---|---|---|
| `app-agent/run` without pinning | **the device**: machine name, id `24f37e45…`, home folder | 17.3 s |
| the same with `targets: [<device id>]` | **the device**, the same response | 13.6 s |

The probe tool is the `probe_where_am_i` expert: it reads whether the listener's marker
file exists (`~/.extella/device.txt`) and returns the machine name. The cloud has no such
file, so "where" tells execution on the device apart from cloud execution without
guesswork.

**Consequences:**

* **the question "does the interface call the agent or experts?" no longer determines the
  product type.** The only thing that decides is **where the data lives** and whether it
  must stay on the machine;
* products tied to a device can move into the storefront;
* the price of the call is **13–17 seconds** (page → OS → core → listener → back). This
  is the physics of the route: such calls are set up as a background job with visible
  waiting (G4), not waited for synchronously.

**Hence the rule for porting device-bound interfaces: one snapshot call, not many small
ones.** The local bridge answered in **6 ms** — two thousand times faster (G). An
interface built on frequent small requests will become unworkable if ported as-is, and
the reason will not be security but the **number of calls**. The rewrite must go like
this: the expert gathers state on the device and hands it back **in a single response**,
and from there the page works with what it already has in hand. Whatever doesn't fit
this model is left in the local version, and this is **said in words on the screen**,
not left to be discovered by silence.

**AMENDMENT a few hours after the probe: this now requires the `device.run` right.** On
the same day the platform rolled out app permissions (H12): `targets` goes through
**only** if the buyer has granted `device.run`, otherwise it is stripped and the expert
runs in a container, not on the machine. Our probe was made before that, which is why
both calls went to the device.

In practice: **the page part of a device-bound product must request `device.run` at
publication time.** If it didn't, the snapshot from the machine won't arrive, and the
product will still look like it's working. The buyer revoking the right is also a normal
situation: say so in words, don't show a blank screen.

**What the probe did NOT prove (do not present as proven):** it was made on the owner's
account, where the buyer and the author are the same person and the listener is
guaranteed to be alive. Whether the path to the device works the same way for an
**unrelated buyer** has not been checked. It is checked with a single purchase by a
colleague. And the obvious point: **if the buyer has no live listener, there is no
device at all** — the page part must work honestly without one, rather than showing a
blank screen.
