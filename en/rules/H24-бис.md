# H24-bis. The THREE SANDBOX DOORS behave differently

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H24-bis. The THREE SANDBOX DOORS behave differently

**Clarified by the Schema Board chat on 16 Aug 2026.** "Storage is closed" is actually
three different doors:

| door | behavior | what to shim it with |
|---|---|---|
| `localStorage` / `sessionStorage` | stays silent, work is lost silently | substitution → a file on disk |
| `document.cookie` | throws `SecurityError` | an in-memory jar |
| `IndexedDB` | throws `SecurityError` | a polite refusal via an event |

**The silent door is dangerous for data, the throwing ones bring the whole app down.**
Excalidraw crashed on the very first line that read a cookie: a white screen, and the
reason sits in a console that doesn't exist inside the OS window. All three must be
shimmed, but only where the native behavior throws: you must not break something that
works for the sake of a safety net.

**Four more errors from the same family:**

* an app may **intentionally not save in a background tab** — check only in the visible
  window, otherwise you'll call someone else's optimization a defect;
* **a service worker takes over the whole port**; renaming files isn't enough — the
  registration lives in the browser separately, a new port is more reliable;
* **your own stub must mark its own refusal**, otherwise the window will declare a
  working app crashed on its own polite refusal;
* **metadata sent with a version lands on the version.** The CARD's name, description
  and tags live on the listing and are changed separately — `POST
  /api/edit-listing/{id}`. This is an amendment to H23.

**The method that worked after five blind loops: make the window name the cause itself**
— "the browser didn't let it in" / "the app is silent" / "the app crashed: name, message,
file:line, stack." **Build the diagnostics as the first step, not the seventh.**
