# H55. An immutable release: the expert keeps running on the previous code

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H55. An immutable release: the expert keeps running on the previous code

**Probe from the embedded-product chat, 13 Aug 2026.** After a rebuild, the expert kept
referencing the previous immutable release. Old releases are deliberately not deleted,
so nothing crashed: the live call executed successfully — on the old code. Externally
this came out strange: the page got "method unavailable," even though the method was
already sitting in the repository.

**Why this is dangerous.** The refusal arrives somewhere other than the cause, and says
nothing about it. People go troubleshoot the page and the method, when the actual issue
is which release is baked into the expert.

**What to do.** The fact that "the new release is installed" is not enough. Verify with
a separate check that the exact release id is baked INTO the expert itself, and re-read
the expert's body by querying it, rather than trusting the install report. This is a
specific case of H38-P: success of an operation is not a fact.
