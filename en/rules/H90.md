# H90. "Zero human actions" was written for macOS: on Windows the token isn't written to disk

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H90. "Zero human actions" was written for macOS: on Windows the token isn't written to disk

A measurement with a colleague on Windows: the app is open, login done, the listener is alive
(uvx, python, ten processes) — but this build puts only `device.txt` into `~/.extella`. The
`os.extella.ai` token lives in the app's memory and goes out as a header on requests; unlike
macOS, it is not written to disk. The connection script (`platform_client.py`) looks for
`~/.extella/os_token.txt` — and, not finding it, used to lie: "open the app, the file will
appear on its own," even though the app was already open.

**Rule.** The promise "zero human actions" holds only where a platform component itself writes
the token to disk; that's macOS. On Windows there is no such component — the promise is false,
and this is a platform gap, not a machine breakage. Until the build is brought in line:

- the script must **honestly** say the file is absent and why (`platform_client.py` is already
  fixed), instead of advising the useless "open the app";
- before sending a human into the browser console, check whether the app persists the login in
  its own storage (on Windows — `%APPDATA%`): the absence of the string `os_token` in the app's
  code doesn't prove the token isn't on disk under a different name. If it's there, the expert
  reads it on an already-authorized device — zero steps for the human;
- manually seeding the file (console → clipboard → file) is a last resort, done once, and the
  token's value is never printed to chat or screen.

The correct fix belongs on the build side — the Windows app should write the token to disk the
same way macOS does. Then "zero actions" will become true (an item for the letter to the
platform).
