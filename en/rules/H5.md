# H5. A page CAN call its own agent — through an app-token

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H5. A page CAN call its own agent — through an app-token

**The limitation was lifted by the platform on 12 Aug 2026.** The earlier edition of this
section said "a page cannot call either an agent or an expert" — this was true exactly
until the `app_token` mechanism appeared. Measured by a live probe the same day.

**Confirmed a second time on 19 Aug 2026, by someone else's probe on a hybrid product.**
The same conclusion was reached independently: the page gets a state snapshot with a
single expert call on a pinned device, which requires the rights to run an expert and to
reach the device. A caveat from that same probe: detailed local actions still stay in the
archived part — the page makes a snapshot, not the work itself.

**How this works.** `{{app_token}}` is substituted into index — an encrypted, expiring
capability (TTL 2 hours, refreshed by reloading the page), carrying inside it the bundle
`{token, listing_id, expiry}`. Two narrow endpoints accept it:

| Endpoint | Body | What it does |
|---|---|---|
| `POST /api/app-agent/run` | `{app_token, expert_name, params}` | runs an expert of its own agent |
| `POST /api/app-agent/message` | `{app_token, payload}` | dialogue with the agent |

The binding is re-read on every call from the purchase and nailed down with a header —
other people's agents are out of reach. Limits: 30 calls per 60 s, body ≤ 64 KB. A leaked
app-token costs the attacker only "this app's agent until it expires," not the account.

**Probe (live test, page-type product, pre-release):**

| Check | Result |
|---|---|
| `{{app_token}}` substituted | yes, 204 characters |
| `app-agent/run` with a nonexistent expert | **the channel is open**: 3,656 ms, the core answers "Expert not found" |
| `app-agent/message` | **doesn't work**: `422 {'loc':['body','agent_id']}` — see below |
| The core directly (`api.extella.ai`) | closed, and rightly so: CORS was never opened for pages |
| The OS's own API | 200 |

**What this changes for choosing the type.** The question "does the interface call the
agent or experts?" no longer automatically sends the product into the device channel: a
page-type product can now do this too. What remains decisive is the first question —
**is something needed on the user's computer** (local files, 1C, services). Data on the
machine → device-bound; logic in the browser or in the agent's capabilities →
page-type.

**Two open observations (reported to the platform's author on 12 Aug 2026):**

1. `app-agent/message` always fails: the core requires `agent_id` not only in the header
   but also in the request body. The same class as the already-seen error with
   `agent/run`.
2. **`{{token}}` is substituted into index unconditionally** — regardless of
   `page_headers`. The page receives the buyer's full account token (36 characters, the
   same one used to open the core). That is, a seller who writes `{{token}}` into their
   page gets the buyer's entire token. As long as this is the case — **use
   `{{app_token}}` in your own products and do not request `{{token}}` at all**: you
   don't need it, and you carry the liability for it.
