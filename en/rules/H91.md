# H91. Listener state files don't sit at a fixed path — don't infer "no listener" from them

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H91. Listener state files don't sit at a fixed path — don't infer "no listener" from them

A measurement on the test stand (a VPS, user ubuntu, 05 Sep 2026): `~/.extella/device.txt` is
absent, even though the listener is running and executing jobs — it stores the device
differently. This is the same disease as H90 (the token on Windows isn't on disk): the path to
the listener's device state is **not guaranteed** and varies by OS, user, and build. Experts
that look for this specific file wrongly conclude the listener is absent.

**Rule.** Check the listener's presence/operation by fact (a process, a live response to a
job), not by the presence of a specific file in `~/.extella`. If an expert needs `device_id`,
get it through the standard path, not by reading an assumed file; the file's absence ≠ the
listener's absence.
