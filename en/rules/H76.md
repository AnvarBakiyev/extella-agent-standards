# H76. The version's scope is a frozen snapshot of expert code

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H76. The version's scope is a frozen snapshot of expert code

**Measured 22 Aug 2026.** The expert `journey_publish` was rewritten, saved via
`/api/expert/save`, read back and diffed character by character — the record in the account is
new. The direct path (`/api/expert/run` with `X-Agent-Id`) executes the new code. The buyer
path (`/api/app-agent/run` with an app token) answers "unexpected keyword argument" — it
executes the **old signature**: the version's scope stores not expert names but frozen copies
of their code, taken at the moment of `add-version`.

**Consequences.**
1. `edit-version` changes only the page — it never updates buyers' expert code.
2. `expert/save` updates the agent's record — the direct path sees it, the buyer path does not.
3. The only way to get new expert code to buyers is a new listing version (once published, it
   goes public immediately, H20). The snapshot is rebuilt from the source agent's experts at
   the moment of add-version.
4. Checking "the expert has updated" must go through a buyer call, not `expert/get`: reading
   shows the agent's record, the buyer executes the copy.
