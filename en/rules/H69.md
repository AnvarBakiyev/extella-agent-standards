# H69. What passes acceptance is the final ZIP in a clean room, not the source tree

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H69. What passes acceptance is the final ZIP in a clean room, not the source tree

An Odoo builder product passed dev-smoke and then failed for a buyer twice in a row
(probe from an outside chat, a build on the Docker track, versions 0.1.1 and 0.1.3).
Both times the cause was not in the product's code, but in the fact that what was
checked was **not what actually ships to the client**.

**Rule.** Before `add-version-stream` and before Publish, run the **final ZIP** (not the
source tree) in a clean room equivalent to the buyer's machine:

- an empty product home folder and empty volumes — nothing left over from past runs;
- **the exact, stripped-down environment of the installed Expert**, not the developer's
  PATH;
- the same mounted folders and the same sequence of states:
  `not installed → ready → restart → ready`.

Dev-smoke with a different PATH does not count as acceptance. If it doesn't pass, do not
create the version to be shipped: a version in the store is immutable (H8), a fix will
only ship as a new number, and the failed version stays forever.

Two concrete failures under this rule, both from the service's stripped-down
environment — **the same root cause as H68**:

- **A stripped PATH hides an external tool.** `docker` from the stripped PATH could not
  find its credential helper, and the install got stuck. Exactly like the CSPL handler
  not seeing `go`/`rustc` from `~/.cargo/bin`: the desktop app gives the service
  `PATH=/usr/bin:/bin:/usr/sbin:/sbin`. Look for the tool yourself and add its directory
  to the environment, rather than relying on the bare name.
- **A mounted shell file inside Docker Desktop is not executable** (`Permission denied`
  on a host mount). Pass the command as content instead — for example, SQL via stdin —
  rather than counting on an executable bind-mount.
