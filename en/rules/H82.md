# H82. A recipe module with no check and no imprint is a lottery, not a product

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H82. A recipe module with no check and no imprint is a lottery, not a product

**The owner's intent, 26 Aug 2026.** A capability is sold not as a program but as a recipe: the
agent assembles it for the human on the spot out of platform bricks. The intent is sound — an
expert, a rule, a concept, and an agent are all created programmatically, so a module is
instructions for how to assemble them. This is how a market of modules opens without a single
change to the platform.

**Where it falls apart.** A prompt is not an artifact, it's a promise of an artifact. The same
text on two machines, with two models, on two different days will give a different result. A
store where the module is reassembled anew each time is selling uncertainty.

**The norm: a module is three parts plus an imprint.**
1. **Recipe** — what to build and how; read by the agent.
2. **Passport** — what is needed and **what the module does NOT do**; read by the human. The
   boundary is mandatory: without it the module promises everything and answers for nothing.
3. **Check** — a machine test able to fail; it has its own negative control. Without a check,
   "it installed" means nothing — this corpus has three separate cases on record of green
   checks over a dead product.
4. **Module imprint** — a file with the expert's code, frozen after the first build. The recipe
   is needed once; after that everyone gets the same thing.

**A module imprint and a version snapshot are different objects.** We make the imprint, and it
lives as a file in the repository. The platform makes the snapshot when a version is released:
it copies the experts' code into the version, and the buyer gets a copy of that, not whatever
the author has right now (H76). The words sound alike, the layers are different — the owner
tripped on this in a conversation on 27 Aug 2026, so anyone will trip on it. In writing, spell
it out: "module imprint," "version snapshot," never just "imprint" or "snapshot" for the
platform one without qualification.

**The recipe's boundary.** A recipe assembles what already exists and doesn't add what's
missing. "Speech recognition" cannot be assembled by recipe today: the microphone in the window
returns a mute track instead of a refusal. The passport must name this before the purchase, not
after.

**The first module as a sample.** "Contract reading": reads with a local model, doesn't send
the text out (a contract is client data), doesn't parse a PDF blindly, and refuses in words; the
response names what it read with and where. Measured 26 Aug 2026 — 6 of 7 fields, 14.7 s
through the platform on a device. The miss on one field is recorded in the passport: a check
requires a threshold, not perfection, or the test gets fitted to the lucky run.
