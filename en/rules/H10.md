# H10. One listing carries BOTH an archive AND a page — that's not two products

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H10. One listing carries BOTH an archive AND a page — that's not two products

The common fork "archive or page" is in fact a false one. A single version accepts **three
separate files** (`POST /api/publish-stream`, `multipart/form-data`, cross-checked against the store
schema on 12 Aug 2026):

| Field | What we put in it | What the buyer gets |
|---|---|---|
| `archive` | product zip + `install.py` | the local part: services, `.state`, keys, file access |
| `page` | interface zip with `index.html` | the surface in the OS window, a desktop shortcut |
| `icon` | 512 px PNG | the icon |

From this, **the hybrid is a standard product type, not a compromise one**: data and keys live on
the machine (archive), the interface is served from the OS (page), and between them sits a call to
an expert that runs on the device (H5-bis). The client's data never leaves the perimeter this way —
only what the person already sees on screen goes out.

**External fonts work in the sandbox** (verified 12 Aug 2026 on a live OS window): the page pulled in
Google Fonts, and the serif headings rendered. Fallbacks are still mandatory — the font may fail to
arrive, and the text must still be readable.

**The page can be replaced without creating a version — VERIFIED LIVE on 13 Aug 2026** on an already
published listing ("Development on Extella", version 1.0.0). `POST /api/edit-version/{vid}`
accepts `page` (and `archive`); `remove_page` removes it. What was confirmed in the live run:

* the new text is visible in the window immediately — before the edit it wasn't there;
* **the version number did not change** — no new version appeared;
* **`Publish` did not need to be pressed again** — the listing stayed in the store;
* nothing broke for those who already installed the product: the shortcut is the same, no
  reinstall required.

So editing the interface is a "change the file" operation, not a "cut a release" one. This changes
the economics of page-type products: text, hints, and layout can be edited daily.

The flip side from H8 still stands: the index is served by the purchased version, while assets come
from the latest version that has a page. For a single HTML file this doesn't matter (the index is
the entire product); for a zip bundle, only change assets compatibly.
