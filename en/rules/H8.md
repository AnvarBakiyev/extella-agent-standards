# H8. Publishing, versions, deletion

### H8. Publishing, versions, deletion

Publishing creates a **pre-release** (`published=0`): visible only to the author. To the store —
`POST /api/listing/{lid}/publish` with `{"published": true}`.

The agent's snapshot is frozen at the moment of publishing: further edits to the agent will
land only in the next version (`POST /api/add-version-stream/{lid}`).

A purchase is pinned to a version. **The index is served by the purchased version, but the
bundle's assets come from the latest version that has a page.** This means: an incompatible
change to assets will break buyers pinned to an old index. Change assets only compatibly.

Deletion (verified 11 Aug 2026, and this is a **correction to my earlier conclusion**):
`DELETE /api/version/{vid}` and `DELETE /api/listing/{lid}` **exist and work** — they answer
`409` while there are purchases ("unpublish it instead of deleting"). The earlier note "there's
nothing to delete with, 405" was wrong. The practical consequence remains: a storefront listing
that anyone has bought (including our own test purchases) cannot be deleted — only unpublished.
