# H72. `/api/app-agent/run` envelopes also carry `status` — the domain check goes blind on it

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H72. `/api/app-agent/run` envelopes also carry `status` — the domain check goes blind on it

**Measured 22 Aug 2026, the "Building on Extella" page, 3.7.0.** The response on the
buyer route arrives in two wrappers, and both look like a domain response:

    {"status":"ok", "agent_id":"…", "result":
      {"status":"success", "expert_name":"journey_capabilities", "result":"{…json as a string…}"}}

Unwrapping was guarded by "a domain response must never be unwrapped: it can have its own
`result` field," and the sign of a domain response was taken to be a **string `status`**. On
this route the guard fires on the very first wrapper: the envelope is returned upward, its
`status === 'ok'`, the domain check `!== 'success'` fails silently — no console error, no
refusal on screen, just nothing happens. One layer got stripped — and it got worse: the
execution envelope carries `status:'success'`, the check lets it through, but there are no
response fields inside it, and the page honestly draws "no credits, no model, no Board" at
51,557 credits and a running model.

**The sign of transport is not `status` but a pair.** A wrapper is given away by the `result`
field together with `status === 'ok'` **or** with `expert_name`. Both are set by the
platform; a domain response answers `success/error/empty/refused` and never carries
`expert_name`. Unwrap while this pair holds — and only then check the domain (a continuation
of H56: transport and domain separate completely, including the sign used to recognize
transport).

**Why this is more dangerous than an ordinary breakage.** The local bridge
`/api/expert/run` returns a different shape, and the same code passes on it. So the check
on the bridge is green while for the buyer **everything** is dead — not one call, but every
one. Checking the buyer route requires a buyer call, without exception.
