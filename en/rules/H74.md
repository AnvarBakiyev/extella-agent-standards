# H74. Unbounded page self-repeat — a pipeline of tasks behind a stuck button

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H74. Unbounded page self-repeat — a pipeline of tasks behind a stuck button

**Measured 22 Aug 2026, a Claude install at a buyer's.** The button held "Connecting…" for
four hours, the device's task counter grew from 201 to 279 — 78 tasks in 232 minutes, about
three minutes per task — with **three** button presses and zero active tasks. The tasks were
not spawned by a human: inside the framed install path lived a watcher — polling `status`
every 90 seconds — that had **neither a retry limit nor a death on handoff**: the eight-second
fallback exit handed the install over to the direct path but never set the completion flag, so
the watcher kept living as long as the window was open. It could not read "done" because of
H72 — it got an envelope instead of a response — and every one of its polls became a real task
on the device. 90 seconds of waiting plus the call's own time — that's the three minutes per
cycle; the arithmetic matched the counter.

**Three norms.**
1. **Every page self-repeat is finite.** Polling, a watcher, a retry after a deferred task —
   all of it has a limit on attempts or time, and once it's exhausted, honest words that it
   didn't work and what to do next. The advice "press again" with no limit inside is offloading
   an infinite loop onto a human's finger.
2. **A watcher dies together with the wait.** Any path that hands work off to another one (a
   fallback exit, a channel refusal) must extinguish its own background retries with the same
   flag that extinguishes success.
3. **A repeat is not new work.** Polling reads state (`status`), it does not re-launch the
   stage; stages are idempotent, so that pressing again continues instead of spawning more.

Checked by the page contract (`test_page_contract.mjs`): limits on the watcher and long
polling, the watcher's death on the fallback exit, unwrapping both envelopes of the buyer
path.
