# H37. An expert that will run for anyone calls nothing external

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H37. An expert that will run for anyone calls nothing external

**A technique from the Data Privacy product chat, proposed for the shared canon on
21 Aug 2026.** Three rules with one root: anything an expert expects from the outside
may be missing at the client's, and its absence will be silent.

**1. Don't import the engine from files that sit at the author's location.** The code is
embedded right into the expert itself. Importing from a neighboring directory works on
the author's machine and nowhere else.

**2. Don't rely on installing packages at run time.** Installing a package from the
network doesn't work inside the listener's sandbox, and the install path never even runs
at the author's — the package is already there, so the refusal doesn't reproduce. Parse
formats using the language's own tools: office-suite documents are an archive with markup
inside, no separate reading library is needed.

**3. Set up any key or state yourself.** Don't expect a key to already exist. Probe: a
mapping table wasn't saved, because it was encrypted with a key the second person didn't
have. Masking ran fine, the reverse operation created a file, and inside it the markers
were left untouched: zero replaced, not a word about the error. The product must create
the key itself, and must always write the table — with no encryption library available,
write it as plain text with owner-only permissions.

**The only check that proves anything.** Run the expert on a clean machine, one with none
of the product's source files and not a single package installed. It works — it's ready
for a client. This catches the whole "works for the author" class before someone on the
other side catches it.

**A related trap from the same probe.** Markup parsing: some writer libraries encode
Cyrillic as numeric character references like `&#1048;`, and the standard reverse
conversion function does not expand them. The engine saw references instead of the word
and **did not mask personal data, without saying so**. A custom parser for numeric
references in both forms, decimal and hexadecimal, is needed.
