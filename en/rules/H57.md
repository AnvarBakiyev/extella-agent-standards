# H57. Channel health cannot be measured by an operation that grows with the log

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H57. Channel health cannot be measured by an operation that grows with the log

**Probe from the same chat, 12 Aug 2026.** The channel watcher was crashing while
reading a system log that had grown too large, against an eight-second cutoff. The timer
kept ticking, but the service stayed in a failed state, and the dead heartbeat had to be
raised by hand. By that point the log had grown to 921 megabytes.

**Rule.** A liveness check must have a constant cost. An operation whose time grows with
the data is not fit for this: it will itself become the cause of failure exactly when it
is needed most. Cap log reading by number of lines and give it its own cutoff, and cap
the log's growth on the server.

**And how a channel should be checked — a template from the same probe.** Not by the
sign "the window is open" and not by a single heartbeat, but by an end-to-end probe on
behalf of the agent: first a fresh heartbeat and a free queue, then EXACTLY ONE test
request, waiting for a response with the same request id, checking the state transition
from waiting to running to completed — and an empty queue at the end. Keep the first raw
response in full, parse it separately afterward.
