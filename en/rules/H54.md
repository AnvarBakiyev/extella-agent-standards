# H54. `app-agent/run` IS SYNCHRONOUS: the expert returns a terminal result as a value, not a task

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H54. `app-agent/run` IS SYNCHRONOUS: the expert returns a terminal result as a value, not a task

**Analysis with a colleague's chat, 22 Aug 2026.** `app-agent/run` is sugar over
`expert.run`, and it **waits for the expert's return synchronously**, then relays its
value to the page. Probes: without pinning it returned the device and its data in
17.3 s; a nonexistent expert — a terminal error "Expert not found" in 3,656 ms. There is
no separate "wait" flag, waiting is already built in.

**Hence the root of a common error.** If the page gets NON_TERMINAL, it is not the
platform returning early — it's that the **device expert returned a non-terminal**: it
created an internal task and handed back a handle, instead of blocking and returning a
finished result. `app-agent/run` honestly relays whatever the expert returned.

Rule: **the expert on the device returns the terminal result AS THE FUNCTION'S RETURN
VALUE** — it does the work inline and returns the finished thing. No internal task +
waiter: the waiting is done by the platform's own wait inside `app-agent/run`. Then a
single scoped `app_token` call gives a terminal result with no browser polling, no
`task_id` in the browser, no `api.full`, and no second run of the expert.

The exact form:
```
POST /api/app-agent/run     header X-App-Token: {{app_token}}     scope expert.run
body:     {"app_token": "<короткоживущий ключ>", "expert_name": "<эксперт>",
           "params": {...}, "targets": ["<device_id>"]}  # targets требует device.run
response: возвращённое значение эксперта, снятое с транспортной обёртки; вызов блокируется
```
The base is `POST /api/app-agent/call {op:"expert.run", payload:{...}}`. The field
`global` is not allowed on the scoped channel. `targets` is kept only when `device.run`
has been granted separately; without it the gateway strips the pin, and the expert goes
to a container. The order of determining and pinning the device is set by H106.

**The one boundary.** `app-agent/run` has a timeout: work longer than it will not manage
to return a terminal result in time, and the page will again get a non-terminal. This is
already a platform gap — a scoped task-check by `app_token` (reported to the platform
team). But more often the expert returns early and fast — that is an async expert, cured
by a synchronous return, not by waiting on the platform.
