# H89. An empty `agent_id` is the legitimate "not deployed," not a failure

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H89. An empty `agent_id` is the legitimate "not deployed," not a failure

An OS change: the buyer's `/app-page/{lid}/` page now always serves the latest one, and
`{{agent_id}}` can arrive **empty** — the agent was deleted, but the purchase is still alive. A
page that expects a non-empty id fails on this.

**Rule.** An empty `agent_id` is the legitimate state "product purchased, but not deployed," not
an error. The page survives it and says so clearly: it leads to reinstalling (`Reinstall`)
rather than showing a blank screen or crashing. The banner's advice is now a single one —
"click Reinstall"; the earlier wording "Buy & Deploy → Existing agent" is obsolete: the form now
targets the installed agent on its own.

Apps have access to storage (`kv.set/get/list` via app-agent with the Storage scope) and
`POST /api/app-agent/whoami` — a stable account id and a verified email for tying data to a
user. Authors are often unaware of this and complain that "the app doesn't remember anything";
this is a documentation gap, not a missing capability (`whoami` itself is an item in the letter
to the platform).
