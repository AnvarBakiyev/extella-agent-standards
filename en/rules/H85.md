# H85. An indicator is a live ping, not the presence of a setting

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H85. An indicator is a live ping, not the presence of a setting

The product showed a green "connected" as soon as a key was entered — but the key could be
wrong and the login not live (measured on the FDE direction: a deceptive green on key entry; a
separate case — Telegram 2FA, where Telethon creates `me.session` with a DC key BEFORE the
user's login, and the indicator lit up falsely).

**Rule.** A status indicator reflects the **result of a live check**, not the fact that a config
is present. Green is set only after a real ping (status loaded, the service answered), and it
goes out if the check fails. For a multi-step login (2FA) — green only when everything is in
place: both the session and the key. "The setting is filled in" ≠ "the login works."
