# H35. A listing's version is a SNAPSHOT: reinstalling silently rolls back an expert's edit

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H35. A listing's version is a SNAPSHOT: reinstalling silently rolls back an expert's edit

**Found by the Data Privacy product chat, 20 Aug 2026. Severity — blocking.**

A version in the store carries a snapshot of the agent's experts, taken at the moment of
publishing. A live edit to an expert does not make it into the snapshot. Every
reinstallation unpacks the snapshot over the live code and **brings back the old
version**.

**How it shows up.** The expert is edited, a re-read confirms the new code, everything
checks out. After a reinstall, the method disappears. There is no error at any step.
Probe: the code shrank from 12673 to 8393 bytes — that is, the rollback is only visible
by size, and only if you specifically measure it.

**What to do.** After editing an expert, cut a NEW version (`add-version-stream` with
`source_type=agent` and `source_id`): the snapshot will capture the current code. The
check: reinstall and confirm the edit holds. A listing that has an outside buyer cannot
be deleted: `DELETE` answers 409, so adding a version is the only option left.

**Why this is more dangerous than an ordinary rollback.** The edit looks applied for
exactly as long as nobody reinstalls the product. For the author, that might not happen
for weeks; for a buyer, it can happen on the very first update.
