# H5-quinta. Two silent dead ends of the shortcut

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H5-quinta. Two silent dead ends of the shortcut

Both look like "the product is broken," even though nothing is:

* **a page added to a version AFTER purchase does not create a shortcut** — the platform
  places it at install time. Only the agent will remain on the desktop, clicking it will
  open the chat, and the person will decide there is no interface at all.

  **The fix is not reinstalling — an amendment from the Recruiter chat, 13 Aug 2026.**
  The canon used to say "reinstall the purchase," but reinstalling also resolves the
  agent question along the way and can hand out a **new** one, breaking the product's
  binding to the current one (H5-ter). Cheaper and more reversible — create a shortcut of
  the same form as the working ones: `POST /api/desktop/shortcut` with the address
  `/app-page/{lid}/` **with the trailing slash** and **without a single header**
  (H5-quinta below). Verified: a shortcut created this way works, the desktop went from
  7 to 8;
* **a shortcut created by hand answers `401 X-Extella-Token header required`** — and this
  is exactly where my earlier wording was not only incomplete but harmful.

> ⚠️ **AMENDMENT 13 Aug 2026, and it matters: the shortcut does NOT need a token
> header.** This used to say "setting up a shortcut by hand is two steps: create it, then
> hang headers on it." From that one could read "write `X-Extella-Token: {{token}}`" —
> and one of the chats advised the owner to do exactly that.
>
> **Probe:** on a live desktop there are **seven app shortcuts, all with zero headers**
> — and they work, including the published guide and the ticket-analytics demo. The page
> identifies the caller by the internal `X-OS-Caller`, which the OS proxy supplies itself
> for requests to `/app-page`. The token header is only a fallback path for a direct
> call bypassing the OS.
>
> **So `401` means not "no header," but "the request did not come through the OS proxy."**
> Causes, by frequency: an address without the **trailing slash**; an address that is not
> `/app-page/{lid}/` but something else; a shortcut created as a plain web app on an
> arbitrary URL.
>
> **The fix is not a header, but the correct shortcut:** the one the platform creates
> itself at install time (`/app-page/{lid}/` with the slash). It is already on the
> desktop after purchase; if it's missing — reinstall the purchase, don't add headers.
>
> **Why this is not a small matter:** `{{token}}` in a shortcut's headers hands the page
> a **full-rights account token** and triggers a consent dialog for the buyer (H11). In
> other words, the advice "write the token" turns a working install into a product with
> excess permissions — and that gets you delisted.
