# H38. A gate at the surface's exit: re-read the artifact, don't trust the transformation

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H38. A gate at the surface's exit: re-read the artifact, don't trust the transformation

**A technique from the Data Privacy product chat, accepted into the canon on 21 Aug
2026.** A companion to H37 along a different axis: H37 is responsible for the expert
**running** for anyone; this section is responsible for what it outputs being **safe**
for anyone. Both are needed, neither replaces the other.

**The principle, in one line.** At the boundary of every surface stands a machine check
that re-derives the fact from the finished artifact using the same detectors — and does
not trust the transformation's own report of success. This is the earlier rule "success
does not equal fact," raised from the level of a request to the level of a file.

**Where it sits.** At the exit of the pipeline, the moment the artifact crosses the
boundary. One scanner per CLASS of surface, not one general scanner for everything.

**The client-facing surface — a personal-data scanner.** It runs the same detectors as
the de-identification step, but as a separate pass over the finished file, not over the
string the transformation returned. What's scanned is the **repackaged** document: the
archive is unpacked, and every text node is walked — body, headers/footers, the string
table, comments. This is exactly what catches the case of "replaced in the body, left in
the header." Its own markers are skipped; any match of a supported type within a checked
region is flagged as a residual risk.

**The demo surface — a scanner for real values.** The list of forbidden values is taken
from the original dataset the demo was generated from: figures, names, identifiers. The
synthetic build is scanned. Even one match is a refusal: a demo must be at zero real
data.

**An honest statement is part of the mechanism, not decoration.** The gate never says
there are no leaks. It says: across the supported types and checked regions, no residual
matches were found — and it prints a coverage matrix. What wasn't scanned — images,
documents from snapshots, macros, unvisited nodes — is flagged explicitly, not swallowed
into a blanket "passed."

**Refusal policy.** Client-facing surface: any residue above zero — the artifact is
flagged as a risk, no clean label is issued. Demo surface: a single real value — a hard
ban on publishing.

**The condition without which this technique doesn't work.** The check must be a
SEPARATE pass over the artifact, not the same code path that did the de-identification.
Otherwise the bug hides in both at once and the gate confirms itself.

**An addition to the mechanism, from our own probe on 21 Aug 2026.** A separate pass
isn't enough on its own: the scanner must prove it can actually find something. Before
trusting a zero, a known-bad value is planted into what's being checked, and the check
must name it. Probe: a secrets search over 72 history records returned zero, because a
shell variable with a Cyrillic name silently fell apart and the search pattern went out
empty. The planted value exposed this in a second. Before that there was the same class
of bug: a check for "the icon was updated" compared the value against itself and always
passed.

A zero returned by a check that has never once shown red is not proof of cleanliness, but
the absence of a check. Compliance with this part is guarded by
`tools/check_output_gate.py`.
