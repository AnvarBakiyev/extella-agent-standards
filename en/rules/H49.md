### H49. INSTALLING THE BRIDGE AT THE CLIENT'S SITE: source form and keychain access

**Log of the "Building on Extella" chat, 21 Aug 2026. Two errors of the same class, back
to back — "it works for the author."**

1. **A private source repository installs only for the author.** The bridge install
   failed with the refusal "Codex could not add the verified Extella source," with no
   reason given. It worked for the author because access to the private repository sat
   in the macOS keychain — he doesn't see that himself. Fix: distribute from a PUBLIC
   repository.
2. **The `github` source form clones over SSH even for a public repository:**
   `Failed to clone repository: git@github.com: Permission denied (publickey)`. Publishing
   the repository only fixes the previous step — the second error of the same class
   surfaces at `plugin install`. Fix: the form
   `{"source":"url","url":"https://…git","ref":"vX.Y.Z"}` — HTTPS, the tag pin is
   kept.

**Amendment to the earlier rule about SSH.** `claude plugin marketplace add` now
switches to HTTPS on its own and says so (`SSH not configured, cloning via HTTPS`). But
it's the Claude Code client that got fixed, **not the platform**, and only the first
step: `plugin install` still goes to SSH if the source is declared with the `github`
form. Exactly the first half of the rule is lifted, the second stands — declare the
source with the `url` form.

The class is shared with installing the Recruiter at a buyer's site: everything sits and
works for the author, and silently doesn't for the client. Test on a clean machine, not
your own (a test stand, `tools/bench/`).
