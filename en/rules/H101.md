# H101. A PRODUCT MUST HAVE A WORKING STATE WITH NO EXTERNAL DEPENDENCIES

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H101. A PRODUCT MUST HAVE A WORKING STATE WITH NO EXTERNAL DEPENDENCIES

**Source: the 1C Agent chat. This is its answer to the white screen — the disease that half the
products in the storefront suffer from (census 19–20 Sep 2026).**

**Cost.** A white screen instead of an interface is caught neither by script analysis nor by
contract tests: the crash happens on the very first access to an incomplete data snapshot.

**Rule — five requirements, all from real breakages:**

1. **A splash screen from the first frame.** Before the device answers, the panel has no data at
   all; without a splash screen the person sees a bare shell. Show what exactly is happening: "Opening
   your cabinet."
2. **The snapshot is always assumed incomplete.** The panel comes up BEFORE the device confirms;
   the first response arrives without settings and without a list of bases — every call tolerates
   missing fields.
3. **No connection is not empty — it's built-in data.** The product carries a demo slice and opens
   on it, with an honest caption in the footer, "training base · your own 1C is not connected."
   **The absence of a connection is a state, not a refusal.** The demo slice must cover ALL blocks
   of the screen: in their case one block said "connect a base" while the neighboring ones showed
   numbers, and half the screen looked broken.
4. **The absence of the external system is a response, not an exception.** `discover_bases` returns
   an empty list and a hint, not a thrown error.
5. **The OS window must not be reloaded from the page** ([[extella-os-window-reload-kills]]): the
   page is only served with the token in the header, and a `reload` on a 401 kills the window for
   good. Also remember that the window is a sandbox with no origin (`Origin: null`), so any external
   `fetch` gives "Failed to fetch" with no explanation.

**The shape of any refusal:** what happened → why → what to do. The error code is never shown to
the person — the code goes to the log. Verbatim from production:

> The computer with 1C is not responding right now. Wake up the Windows computer and check that
> Extella is running on it (Start), then try again.

Separately, the trick of "the screen says what it could not verify" lowers anxiety: "the
counterparty's BIN is not filled in in 1C — cannot verify" instead of a silent guess.
