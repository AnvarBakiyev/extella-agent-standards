# H70. An ambiguous output before a destructive operation means "stop," not "no data"

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H70. An ambiguous output before a destructive operation means "stop," not "no data"

A check for "does the database exist" read `psql`'s output as `.strip() == "1"`. With any
warning printed before the one, the string stopped equaling `"1"`, and the code concluded
"the database doesn't exist" — meaning it would go delete and recreate it on live data.
Caught by a separate audit before release, but by construction this was a landmine.

**Rule.** Before a destructive operation (delete, recreate, wipe), the tool's output is
parsed **fail-closed**: an explicit expected answer means we continue; anything else,
including empty or "close enough," means we **stop and report**, rather than treat it as
absence. "Unclear" never means "safe to erase."
