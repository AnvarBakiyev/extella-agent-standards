# H108. CONNECTING A CHAT AGENT (Claude, Codex) ON A NEW MACHINE GETS DONE, NOT EXPLAINED

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H108. CONNECTING A CHAT AGENT (Claude, Codex) ON A NEW MACHINE GETS DONE, NOT EXPLAINED

**Measurement, 24 Sep 2026, Extella app 1.3.0.** The app build has not a single mention of
`api_token`, `token.txt`, or `~/.extella/` — **the key is not placed on disk on any system**. So
on every new computer the chat agent is left without a key. The cost is known: colleagues who
moved to new machines all got stuck at once, and our own installer advised "run the app once —
the key will appear on its own," which never happens.

**Rule. The product and the agent must close this themselves, in this order:**

1. **Do it.** The expert `experts/dev_connect_assistant.py` runs on the target machine
   (`targets: [device_id]`): the platform hands it the key, it writes it to
   `~/.extella/api_token.txt` with `600` permissions via a temp file, **verifies it with a live
   call**, and returns only the path and the fingerprint. The key's value is never returned and
   never logged. Live probe, 24 Sep: `{"connected": true, "response": "HTTP 200"}`.
2. **Say it in one action, if it can't be done.** The platform doesn't always hand over the key
   (H5, corrected 17 Aug). In that case the person is told exactly one step: in the app,
   `Library → System → Tokens`, create a token and save it to the same file, or set it in the
   `EXTELLA_API_TOKEN` variable. No "look for the key somewhere."
3. **Verify with a fact, not with the file's presence.** A dead key in the file looks like a
   connection and breaks later. Verify by calling a reading tool; the `initialize` handshake
   passes with any string in place of a key (amendment of 28 Sep 2026, H81).
4. **The key is never forwarded.** Not into chat, not to a colleague, not into a ticket: it gives
   full account access, up to deleting the agent. Every machine and every person has their own key.

**Where this already lives:** the expert — in `experts/`, the connection step in the installer —
`tools/connect_mcp.py` (its refusal points to the tokens screen), the "Assistant on a new
machine" section — in the "Development on Extella" app (`store_app/content.json`, RU+EN),
onboarding for external chat agents — `EXTELLA_AI_ONBOARDING.md`.

**A request to the platform** — letter §32: place the key at sign-in, or give a "connect the
assistant" button. Until it exists, the rule above is our workaround.
