# H109. ONE KEY FOR THE STORE AND FOR THE CORE — ONLY THE HEADERS DIFFER

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H109. ONE KEY FOR THE STORE AND FOR THE CORE — ONLY THE HEADERS DIFFER

**Measurement, 24 Sep 2026,** after reviewing someone else's chat that stalled work over this.
The same `GET /api/my-listings` on `os.extella.ai`:

| what we knock with | response |
|---|---|
| the core key (`~/.extella/api_token.txt`) in the `X-Extella-Token` header | **HTTP 200** |
| the key from `~/.extella/os_token.txt` in the same header | HTTP 200 |
| the core key in the `X-Auth-Token` header | **401 "X-Extella-Token header required"** |

The values of the two keys on the machine differ, but the store accepts both: what matters is
the **header**, not the source file. The core, conversely, requires `X-Auth-Token` — hence the
confusion.

**Rule.** Don't declare publishing impossible because `os_token.txt` is missing. The order is:
take any valid account key (a file on disk, the `EXTELLA_API_TOKEN` variable, or one created by
a person in `Library → System → Tokens`), talk to the store with the `X-Extella-Token` header, to
the core with `X-Auth-Token`. Verify with a fact: `GET /api/my-listings` on `os.extella.ai`.

**The cost of the earlier misconception — a client's education paid for in time.** An external
chat read in our own runbook "the OS personal token lives in `~/.extella/os_token.txt`," got
denied access to that file by the client, and declared: "the GUI app is hitting a platform
limitation, publishing is impossible." There was no limitation: the client had the key, only the
line about the header was missing. Four days of work went into correspondence and reaching out to
the developers.

**What else stopped that same chat** (each one a fact of our own canon that it did not find): the
expert call from the page via `{{app_token}}` and `app-agent/run` (H5-bis, H106) it deemed "not
documented in the public `api.html`"; a deferred run returned HTTP 500 while the work had
completed (H54: `running` is not a result, wait for `check_task`); a 1.56 MB file it tried to pass
in a single call (the 64 KB body limit — read it on the device or send it in chunks).
**Conclusion for the canon: the public `api.html` is not the source of truth.** The source is this
corpus and the runbooks; say so to external chats from the first line.
