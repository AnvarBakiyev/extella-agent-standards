# H81. The entry point contradicted the prompt, and the entry point won

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H81. The entry point contradicted the prompt, and the entry point won

**Measured 26 Aug 2026.** The finished prompt forbade it: "don't ask to have the token
forwarded into chat." The README, step 1, ordered exactly the opposite: "ask the user to type
into Extella chat 'Generate me an API token,' have them send you the string." A contradiction
inside a single entry point — and **the README won**, because the prompt itself sends the agent
to read the README as the source of truth. A human unfamiliar with Extella hit a dead end:
where's the chat, what to type, where to paste the secret.

**Asking wasn't necessary at all.** The key needed is the same one MCP uses.

> **AMENDMENT 28 Sep 2026 — two claims in this paragraph turned out to be wrong.**
> First: the key does NOT appear on disk by itself — app 1.3.0 does not write it, and an
> issue screen does exist (`Library → System → Tokens`), see H108 and the measurement of
> 24 Sep 2026. Second, and this one costs more: **a handshake proves nothing.**
> `initialize` with a deliberately wrong key answers HTTP 200 with `"result"`, and
> `tools/list` returns the tool catalogue with no authorisation at all. A check built on
> the `"result"` substring declared "connected" for any string in place of a key — and the
> newcomer went looking for the fault where there was none (audit of 28 Sep 2026, F01).
> There is exactly one proof: **calling a reading tool and parsing the answer field by
> field** (`isError`, `error`). An empty list on a new account is a legitimate success.

**The norm.** A step a human cannot perform without knowing the platform is not an instruction,
it's a command: `tools/connect_mcp.py`. Three rules inside it:
1. **The key is checked by a call — not by a file's presence and not by a handshake.** A
   file survives an account switch, and a handshake passes with any rubbish in place of a
   key. The honest proof is `tools/call` on a reading tool with `isError` parsed.
1-bis. **`X-Agent-Id` is mandatory in MCP headers — and only in MCP.** Measured 28 Sep 2026:
   the same `tools/call` with a valid key but without this header answers `isError: true`
   and the text "Failed to resolve dependency 'token'" — the message blames the key, though
   the key is valid. **This does not carry over to REST:** `POST /api/agent/list` with the
   same key and NO `X-Agent-Id` answers HTTP 200. A non-empty value is enough (a
   non-existent agent id gives the same answer as a real one — verified on `list_agents`;
   tools that work INSIDE an agent's scope need a real one), so connecting is possible on an
   empty account. **One text for two causes:** MCP answers with the same wording both for a
   wrong key and for an empty agent header.
1-ter. **Ask REST for the cause of an MCP refusal.** Measured 28 Sep 2026: for a wrong key
   REST answers `HTTP 401 {"error":"Invalid or expired token"}`, while MCP at the same
   moment answers HTTP 200 with the text about a "token dependency". If REST returns 200,
   the key is VALID and the MCP headers need fixing, not the token.
2. **The secret goes into neither a config nor arguments.** Claude Code has `headersHelper` for
   this — a script that hands over headers at call time. Codex has none, the key goes into
   `~/.codex/config.toml` — the file is set to 600, and that is said out loud, not left
   unsaid.
3. **What is already configured is not overwritten**: a person may have a pairing to a
   different account.

**A trifle that would have cost silence.** `claude mcp add-json` without `--scope user` writes
the server into the CURRENT folder's scope (`projects.<cwd>` in `~/.claude.json`). The agent
would have reported "connected," and in any other folder the pairing would not exist.

**Also fixed the format for Codex along the way.** The README showed it a `mcpServers` JSON —
that's the Claude Code format. Codex keeps MCP in TOML (`[mcp_servers.*]`,
`~/.codex/config.toml`); following the old example, it would not connect.
