# H17. An expert's response arrives in TWO wrappers, and a dict is not serialized as JSON

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H17. An expert's response arrives in TWO wrappers, and a dict is not serialized as JSON

**Caught on a live product on 14 Aug 2026.** The page opened, said "log on your machine," and
showed "**undefined** solutions." Not a single error in the console: yet another silent refusal,
and this time in our own product.

Two causes, both non-obvious:

1. **There are two wrappers.** The OS gateway puts the core's response inside `result`, and the
   core puts the expert's result inside **its own** `result`. Unwrapping only one wrapper gives an
   object that lacks the fields you need — and the code calmly moves on;
2. **A dict returned by the expert is serialized with Python's `repr`** — single quotes, `True`,
   `None`. This is **not JSON**, and `JSON.parse` won't take it.

**The fix belongs in the expert, not the page:** return `json.dumps(...)`, i.e. a **JSON string**.
Then the response parses unambiguously, and the rule holds for any product.

**And the broader rule behind this case:** success means not "a response arrived," but **"a
response of the shape we expect."** The page must validate the shape (in our case — that `total`
is a number) and say so in words if something else arrives. Otherwise the product cheerfully
reports success while showing `undefined`.
