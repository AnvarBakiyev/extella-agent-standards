# H77. A product that creates products must place the icon itself

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H77. A product that creates products must place the icon itself

**Measured 23 Aug 2026.** The "Day One" storefront created an app draft with no icon. On the
desktop it landed as a nameless gray square among Bronze Engraved tiles — a reward for
completing the journey looked like litter, and the owner asked to have it removed. The
storefront gate (`check_listing_meta`) requires an icon for repository products, but it does
not apply to listings that a product creates **at runtime**: there is no folder there to check.

**The norm.** Any step that creates a listing attaches `icon` in the same `publish-stream`. The
tile is not drawn on the spot: there is one style canon — `tools/bronze_icon.py`. There is no
Chrome and no Lucide set on the device, so the tile is rendered by the canonical generator
ahead of time and baked into the expert as an image (base64). A "roughly the same" generator of
one's own inside the expert is a second source of style — exactly the class of divergence the
gates exist against.

Check it not by a response field but through the storefront: `has_icon` in
`/api/my-listings`. The expert's response only says it **sent** the icon.
