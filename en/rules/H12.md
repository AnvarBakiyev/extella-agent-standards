# H12. App permissions (`app_scopes`) — a new mandatory publishing step

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H12. App permissions (`app_scopes`) — a new mandatory publishing step

**Appeared on 12 Aug 2026, rolled out the same day.** Cross-checked against the live OS schema: the
`app_scopes` field exists at publish time, the endpoints `/api/app-agent/call` and
`/api/app-permissions/{lid}` are live. Between my two checks within the same day the schema
changed — **verify live, not against yesterday's record.**

**The main rule, whose violation kills a product silently:**

> **An empty `app_scopes` means the app cannot reach the agent's API at all.**
> Nothing is granted by default.

The page will still open and look intact — and every call will return `403`. A product published
without declared permissions looks like it works and doesn't.

| Permission | What it grants |
|---|---|
| `agent.run` | a dialogue with the agent |
| `expert.run` | running the agent's experts **in a container** (cloud) |
| `device.run` | `expert.run` + `targets` — **running on the buyer's device**, a separate permission |
| `expert.read` | `expert.list` / `get` / `search` |
| `concept.read` / `concept.write` | the agent's memory |
| `kv.read` / `kv.write` | key-value |
| `rules.read` / `rules.write` | the agent's rules |
| **`api.full`** | **the entire account** via `/api/ext/core` — for management apps (H15) |

Calls are `POST /api/app-agent/call {app_token, op, payload}`; `/run` and `/message` are sugar over
`expert.run` and `agent.run` and require the same permissions. The gateway always strips `global`.
It passes through the `targets` field only when `device.run` has been granted; without that
permission the call runs in the container. A scoped operation never reaches beyond the buyer's
agent.

**Three consequences for our work:**

1. **Declare the minimum.** The buyer sees the requested permissions on the card before installing.
   A product asking for `*.write` "just in case" looks dangerous — and rightly so. This is the same
   stop-rule as the ban on `delete_*`, only now the client sees it too.
2. **Permissions can be revoked at any time** (`POST /api/app-permissions/{lid}`, `[]` — full
   revocation), and the check runs on every call. So `403` is a **normal, standard state**, not an
   incident: the product must say in words "the permission was revoked, enable it here," not show a
   blank screen.
3. **The agent's front end is not the same as fleet management — but a way out appeared the same
   day.** `app_token` is pinned to **your own** agent from your own install; someone else's agent
   isn't reachable through the normal permissions. The earlier conclusion, "so Console needs a
   fully privileged `{{token}}` or a device-side path," is **withdrawn**: there's now the `api.full`
   permission and the forward proxy (H15), where the token never enters the JS at all. Asking for
   `api.full` in a product that only needs its own agent is a defect.
