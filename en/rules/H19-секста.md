### H19-sexta. THE OS'S LOOK IS NOT CHANGED BY AN EXTENSION — my mistake, and it cost the owner time

**Measurement, 14 Aug 2026. I claimed that an "edition theme" was possible via an extension, built
one, published it, and installed it on the owner's live machine. It did not work, and here's why.**

The OS shell's page (`GET /desktop`) has **not a single mention of injecting extensions** — no
`extension`, no `userScript`, no `inject`. Extensions are mixed in by the **OS's built-in browser,
into the pages it opens**; the shell itself is not a browser page.

So:

* **the OS's look is not changed by an extension.** Not the color, not the background, not the
  desktop layout;
* **the windows of your own apps — yes** (historical confirmation: the Recruiter panel's shell
  worked exactly this way), but a product already paints its own window with its own CSS, no
  extension needed.

**What follows from this for editions, and this is the third reversal in a day:** "an edition
changes the environment's look" — impossible today. An edition can give a **coherent look inside
its own windows** and a common set of apps. Nothing more.

**How I got caught by this.** I checked the shell's CSS variable names (`--p`, `--ph` — they
matched), saw the match, and considered the mechanism proven. What matched was the **names**, not
the **fact that code was actually being delivered**. Rule: you have to prove the whole path, not
the link that's easiest to check.

The theme listing has been deleted, the desktop entry removed, the extension library is empty.

**A trace left in the gate (14 Aug 2026, evening).** `check_edition` kept REQUIRING a theme file
from every edition — that is, forcing a known-dead file into the composition and promising in
green that it did something. The requirement has been dropped: the theme is checked only if the
edition declared it; a declared-but-missing one is still an error. Both cases are proven by the
self-check. General lesson: **a refuted rule has to be removed not just from the text, but from the
gate too** — otherwise it keeps living and keeps binding people.
