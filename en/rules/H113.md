# H113. A NUMBER ABOUT ANOTHER FILE IS NEVER WRITTEN BY HAND

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H113. A NUMBER ABOUT ANOTHER FILE IS NEVER WRITTEN BY HAND

**Measurements 24–25 Sep 2026, four cases in one day.** "116 rules" in the entry point — an hour
later there were 118. "About 10 KB" for the index — 16 KB in bytes. "9 KB" for the entry point —
6.7 KB. And a fourth, found by the very measurement itself: `BUILD_STAGES.md`, `START_HERE.md`,
`CONTRIBUTING.md`, and the "Development on Extella" app promised "21 gates" in production and "29
checks" in CI, while the machine required 25 and ran 74. People were preparing a release from this
text.

**Why it's caught by the second reader, not the author.** The number describes ANOTHER file. The
author edits one file, the number lives in another, and at the moment of editing it looks correct.
Review is powerless here: the reader has the same text in front of them, not the fact. In all four
cases it was caught by someone other than the writer.

**Distinguish three kinds of numbers:**

1. **A number about another file — don't write it.** Either a check computes it and cross-checks
   it against disk (file sizes — `check_file_size_claims`; the count of checks —
   `check_counted_claims`), or the text names a command instead of a number. A third legitimate
   option is not to name the value at all, but a property instead: "large, take it section by
   section."
2. **A number about the outside world — date it.** There's nothing to recompute the platform's
   behavior against: "backs off at the 51st second," "body up to 64 KB," "the call takes 13–17
   seconds." Such a number lives with the date it was measured and is only disproved by a new
   measurement.
3. **A number about what's right next to it — is fine.** "Four rules" over four bullet points gets
   edited in the same paragraph together with the list and doesn't silently go stale.

**Check narrowly.** The first edition of `check_counted_claims` gave four false alarms out of
seven — "not a single check," "self-check 10/10," "One check: close the screen," "(21 checks)"
about a single tool's self-check. A false alarm in a gate is more expensive than a miss: people
stop reading it. So the check also requires a subject — it must be about the volume of checks at a
stage, or about what CI runs — and keeps control probes for each of these phrasings.

**And re-check the neighbors of the fixed line.** After removing "2 gates" from `START_HERE.md`,
the same line still had "`prod` — 21": a bare number without the word "gate" wasn't seen by the
pattern. The gate has now been taught this form too.
