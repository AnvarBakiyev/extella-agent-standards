# H97. AGENT/CREATE: THE USER COMES FROM THE TOKEN, NOT FROM THE BODY

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H97. AGENT/CREATE: THE USER COMES FROM THE TOKEN, NOT FROM THE BODY

**Measured (September 2026, the public core).** `POST /api/agent/create` with a minimal body
answers `422` and asks only for `provider` and `model` — there is no `user_id` field in the body
at all, the agent's owner is derived from the token. A token with no user (a global/service
token) passes the check and can read, but on creation it answers `401 Authentication required
(user_id missing)` — measured with the car dealer's client, a global "am-deploy" token; the same
error as in H30 for a POST from an expert, matching our own measurement.

**Rule.** Agents are created with a personal user token (from the OS/account). Use a service or
global token to read and run. Don't build agent creation with a global token into the installer:
for a buyer it will fail with `user_id missing`, and that's not a platform breakage, just the
wrong class of token.
