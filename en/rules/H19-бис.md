### H19-bis. CORRECTION: the extension cannot be removed, editing desktop state doesn't help

On 13 Aug I wrote: "the extension is removed by editing desktop state, it stays in the library."
**The first half is wrong.** On 14 Aug the removed extension **came back onto the desktop by
itself** — the OS rebuilds the list from the account's library.

How I got caught by this: I read the state **right after writing it**, saw the extension was gone,
and considered it done. The state converged later — and brought everything back.

> **Rule: "read right after writing" is not the same as "verified."** Wherever state gets
> reconciled by someone else's process, you have to read it again, after some time has passed.

~~In practice: an installed extension cannot be removed.~~ **Reversed on 14 Aug 2026** — see
H19-quinta: it's removed by deleting the extension's listing. Setting an edition's theme "to try
it" is fine.
