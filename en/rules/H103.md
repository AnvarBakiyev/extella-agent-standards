# H103. BREAKAGES YOU DON'T SEE ON THE DEVELOPER'S MACHINE

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H103. BREAKAGES YOU DON'T SEE ON THE DEVELOPER'S MACHINE

**Source: the 1C Agent chat. Each one cost a session or a release.**

* **The assembled page is a template.** It has `__THIN_INIT_JSON__` in it; the substitution
  happens at serve time. Opened as a file, the page fails with a syntax error and **silently falls
  back to the training base** — the author was recording a video, confident he was working with the
  live one.
* **An end-of-line comment eats the code after it.** An explanatory note added via `//` swallowed a
  function call: the syntax is intact, the tests are green, the write goes through, and the screen
  stays silent. The person clicks again and gets a refusal where everything had actually worked.
* **A new package file, not added to the delivery list,** works for the author and fails for the
  client on import. Guard the delivery contents with a test.
* **"Optional" in an external service's description doesn't mean optional.** Two fields of the ESF
  (electronic invoice) system are marked `minOccurs="0"`, and the production system requires them.
  It's discovered only through a live refusal.
* **The set of fields required for saving and for posting differ.** 1C accepted the document for
  saving and refused to post it. **You have to check with the terminal action**, not an intermediate
  one.
* **Black console windows on Windows.** You need `CREATE_NO_WINDOW` TOGETHER WITH
  `DETACHED_PROCESS`, otherwise the process has no console and every child opens its own window.
  And the flag must be exactly **`0x08000000`**, not `0x00000008` — a typo cost frightening windows
  for the user. *Verified by the canon keeper on 21 Sep 2026: `CREATE_NO_WINDOW = 0x08000000`,
  `DETACHED_PROCESS = 0x00000008` — these are different flags, the correction is right.* Keep
  `CREATE_BREAKAWAY_FROM_JOB = 0x01000000` nearby: without it a process launched inside a job
  (an ssh session, part of the services) dies together with its parent ([[H98]]).
