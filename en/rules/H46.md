# H46. AN INSTALLER ON POSIX ≠ WINDOWS: layout and teardown permissions

### H46. AN INSTALLER ON POSIX ≠ WINDOWS: layout and teardown permissions

**Log of the "1C Agent" chat, 21 Aug 2026. Permission patterns copied from Windows
examples break silently on Mac/Linux.**

1. **`os.chmod(path, stat.S_IWRITE)` on POSIX equals `0200` — "write without read."** On
   reading and walking the directory, this becomes `Permission denied` on your own
   folder: `rmtree` can't even list the contents, and an interrupted reinstall leaves an
   unreadable wreck behind. Correct: `0o700` for directories, `0o600` for files, and
   `unlock_tree` before teardown.
2. **Sealing to read-only is mandatory on POSIX too.** An installer that lays out a
   release without clearing the write bits fails the integrity guard ("directory is
   mutable") even on an intact layout. This is invisible on Windows — the guard skips
   `nt`. Correct: `seal_tree` (files `0444`, directories `0555`) after the layout is done,
   AND on the "already installed" branch — old, intact layouts get sealed retroactively
   by a reinstall, with no re-download.

**A correction to a previous rule.** "`chmod u+rwX` the release directory before
packaging" — went stale within a day and is dangerous (see point 1). Correct: copy the
release into a temporary folder and package the copy, leaving the live directory
untouched.
