# H80. A desktop tile and a store listing are two different things

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H80. A desktop tile and a store listing are two different things

**Measured 23 Aug 2026, continuing H79.** The install places a shortcut on the desktop
(`shortcuts` in the desktop state). Deleting the listing (`DELETE /api/listing/{id}`) does
**not** carry the shortcut away with it: after four trials, three dead tiles remained on the
owner's desktop, leading to deleted pages. Purchase records disappeared together with the
listings — so the shortcut outlives both the purchase and the listing.

**Where shortcuts live.** `GET /api/desktop/items` returns the desktop by sections (`folders`,
`links`, `instructions`, `shortcuts`) — this is NOT a flat list, and a naive `len(response)`
gives zero. The state itself is `GET/POST /api/desktop-state`:
`{state:{pos, shortcuts, folders, sys, trash, links, instructions, …}, rev}`.
There is no separate `DELETE` for a shortcut; it is removed by writing state without it.

**The norm.**
1. Edit desktop state minimally and **diff it before sending**: how many keys change and
   which. A person's desktop is not our draft — it holds their notes, links, and trash.
2. Take a copy of state before writing — a rollback must exist.
3. Don't promise the product "removes with one click": removing it fully means the tile goes
   to the desktop trash **and** the draft goes in the store. A promise that sounds simpler than
   the truth comes back as litter on someone else's desktop.
