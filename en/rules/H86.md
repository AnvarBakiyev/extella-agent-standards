# H86. A test must hit the same path as production — or green masks dead

Full corpus — `DEPLOY_REQUIREMENTS.md`; rule index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/en/rules/INDEX.md).

### H86. A test must hit the same path as production — or green masks dead

Three FDE-direction products independently ran into the same class: **the test is green, and
production is dead.**

- A test mocked `s.send_whatsapp=…` — and by doing so **created** a name that didn't exist in
  production (the function was named differently): sending failed with `NameError`, tests green.
- A test triggered a button handler by **calling the function**, while in production the button
  couldn't be clicked (broken `onclick` markup): the defect went unnoticed.

**Rule.** A test checks the same path production takes: a button — with a **real click**
(`dispatchEvent`), not a function call; a name — the one that actually exists in the code. If a
test mocks a function that doesn't exist in production, it's masking it — check `grep -c 'def '`
before mocking. Replace inline `onclick` in generated strings with `data-*` plus delegation
(see H63): that makes the click path checkable.
