# H19-quater. Updating an extension leaves an old copy on the desktop

Full corpus — `DEPLOY_REQUIREMENTS.md`; rules index — [rules/INDEX.md](https://raw.githubusercontent.com/AnvarBakiyev/extella-agent-standards/main/rules/INDEX.md).

### H19-quater. Updating an extension leaves an old copy on the desktop

Measurement, 14 Aug 2026, while updating an edition's theme: after reinstalling to a fresh version,
the account library has **one** entry (the new one), while the desktop has **two**: the old one and
the new one. Both run.

From this, two things follow:

* **the re-run guard must include the version.** Our flag was shared
  (`__theme_EDITION`), so the old copy claimed it first and **blocked the new one** — the theme
  update silently failed to apply. In the template, the flag is now versioned;
* **a stale copy can be removed from the desktop**, and it stays removed — but only if it's
  **already gone from the library**. This is exactly the precise rule that corrects yesterday's
  mistake:

> **Editing desktop state holds if the record is not in the account library.**
> If the record is still in the library, the OS will bring it back.

Verified twice with a pause of 10 and 25 seconds: the removed stale copy did not come back, the
removed live one (13 Aug) did.
