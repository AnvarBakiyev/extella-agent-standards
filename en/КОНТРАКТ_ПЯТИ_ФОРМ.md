# The Five-Form Contract — the common language of Extella apps

Status: in effect since 19 Aug 2026. Decision owner — the owner.
The executable version of the contract is `tools/формы.py`; if the text and the code
disagree, the code wins, and this document is brought into line.

## Why the contract exists

Every pairing of two apps written by hand costs as much as a separate product.
Three apps give three pairings, and that is tolerable. **Five hundred apps give about
250,000 pairs** — nobody will write that many, and the issue is not the pace of work but the
structure: pairings grow as a product, and effort as a sum.

The contract breaks the count itself. The source app **does not know the recipient**,
the recipient **does not know the source**. Both know only this dictionary. The work
becomes N+M instead of N×M: a new app learns once — and can talk to everyone who
already exists, including those who appear later.

## Five forms, and why there are five

| Form | What it is | Required item fields |
|---|---|---|
| `список` (list) | rows with fields | `имя` (name), optionally `поля` (fields) |
| `число` (number) | one total with a caption | — (the `значение` (value) field at the top) |
| `шаги` (steps) | process stages in order | `имя` (name), optionally `подпись` (caption) |
| `связи` (links) | "A → B" pairs with a caption | `от` (from), `к` (to), optionally `подпись` (caption) |
| `документ` (document) | text by section | `имя` (name), `текст` (text) |

Every form requires a `заголовок` (title): without it a person cannot tell what they are looking at.

**The dictionary is closed on purpose.** A dictionary that grows for every new
app is the same N×M, just written into one file. A new form is added only if it
cannot be expressed with the existing ones, and **this is the owner's decision, not
the convenience of whoever writes the code**. The limit is enforced by a check in
`формы.py`.

Limits: no more than 200 items in a list, no more than 4000 characters in a document
section. More than that is an export or a file, not a picture.

## Duties of the parties

The **source** must bring its content into one of the five forms. If it doesn't
fit — say honestly "doesn't fit": such an app is shown in its own window, not someone
else's. A silent blank is worse than a refusal.

The **recipient** must be able to show all five forms and **must not know a single
source by name**. A real app's name in the recipient's code quietly brings the count
back to N×M — this is checked automatically, including the examples in the
documentation.

**Writing** obeys two rules, and both are about someone else's work:
1. The agent writes only its own elements, marked with the source. It never touches
   anything a human made.
2. A repeat run replaces the previous result of the **same** source and does not touch
   anyone else's. The label separator must be impossible inside the source name —
   otherwise "astra" would erase "astra-new", and there is no boundary.

## How an app connects

1. The installer records the app in the source registry
   (`~/extella-cabinet/источники.json`) — a person never does this by hand.
2. On first contact the model reads the format **once** and returns not a retelling
   but an extraction recipe: the path to the data and the field mapping. The recipe is
   stored as a passport in `~/extella-cabinet/паспорта/`.
3. From then on ordinary code fetches the data. **The model understands — the code
   executes.** The reverse would be slow, expensive and non-deterministic: the same
   file would give different answers each time, and no one could say who is right.
4. A passport is born **unconfirmed**. A misunderstood format draws a confident lie;
   until a person has looked at it, it must not be drawn from.

## Selection is shown, not hidden

If nine items out of a hundred and three are shown, this is written **on the result
itself**, not only in the terminal: the terminal will close, the picture will remain.
No selection is applied by default — if no number was given, everything is shown,
and how many is stated.

## What has been proven

- Churn storefront (columns `churn_pct`, `avg_ltv_k_kzt`) → 40 rows, 29 s.
- **CycloneDX SBOM** — an OWASP standard, 122 KB, a schema Extella has no relation
  to → the model found the path and fields in 42 s, the code fetched 103 entries,
  both recipients displayed it. **Not one line of code for this format.**
- A second recipient (the report page) was added with one file: neither the
  dictionary nor the sources were changed.
