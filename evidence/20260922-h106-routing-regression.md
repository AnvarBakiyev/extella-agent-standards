# H106: живой прогон в окне ОС — блок маршрута без `targets`

Дата: 22.09.2026  
Листинг: `40cf6ccf-10fe-4cd2-989f-702e5ddc8e8b`  
Версия: `0.1.0-pre.4`
Агент установки: `agent_nz1ZRgpDnDKdAXLBABFOJ`  
Ожидаемое устройство: `24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4`

## Что подтверждено

- Страница открыта с рабочего стола настоящей Extella через CDP, не на стенде.
- `{{app_token}}` подставлен ОС.
- Покупке выданы `expert.run` и `device.run`.
- Первый запрос страницы имеет `expert_name=h106probe_where` и не содержит `targets`.
- Тот же `app_token` и тот же эксперт с
  `targets=[24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4]` исполняются на Mac и возвращают
  `pageRoute.targetId`, `device` и `host=Anvars-MacBook-Pro.local`.
- Прямой `/api/expert/run` того же агента без `targets` тоже использует default target
  и возвращает тот же Mac.

## Где расходится платформа

`POST /api/app-agent/run` без `targets` не применяет ожидаемый default target агента и
возвращает:

```text
[Execution Error] invalid decimal literal (<container>, line 1)
```

Это **не облачный Fython** и не синтаксическая ошибка собственного кода. Контроль тем же
`app_token` и тем же экспертом дал:

| Маршрут | Результат |
|---|---|
| без `targets` | `invalid decimal literal (<container>, line 1)` |
| Windows `39f81469…` («Windows с 1С») | та же ошибка дословно |
| VPS `85800354…` | успех, `host=extella-team` |
| Mac `24f37e45…` | успех, `host=Anvars-MacBook-Pro.local` |

Листенер Windows `39f81469…` вошёл в другой аккаунт Extella (H104). Совпадение ответа
показывает, что незакреплённый вызов платформа направляет именно туда. Сам выбранный target
ответ не раскрывает, поэтому это обоснованный вывод из контрольных прогонов, а не поле
ответа платформы. Контрольный «Рекрутёр» и опубликованный «1С Agent AI» дают ту же подпись.

В результате первый обязательный шаг H106 не получает `pageRoute.targetId` или `device`.
Временный продуктовый обход принят в живом окне Агента 1С 1.66.0: объяснить H104 словами,
показать поле Device ID и повторить вызов с явным `targets`. `localStorage` в песочнице
запрещён, поэтому устройство хранится только в памяти открытого окна и при новом открытии
вводится заново. Платформенное исправление описано в §46 письма Тимуру.

## Проверка временного обхода в настоящем окне ОС

Версия `0.1.0-pre.4` установлена из предрелиза и открыта с рабочего стола Extella. Проверен
полный путь из §46:

1. Первый вызов без `targets` получил указанную выше подпись H104.
2. Страница показала причину словами, поле Device ID и кнопку «Работать через это
   устройство»; кнопки продукта не заблокированы молча.
3. После ввода `24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4` проверочный вызов ушёл с
   `targets=[24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4]` и вернул
   `host=Anvars-MacBook-Pro.local`, `platform=Darwin` и тот же `pageRoute.targetId`.
4. Все следующие вызовы сохранили этот `targets`.
5. После повторного открытия окна Device ID снова пуст, обход показан заново.
6. Запись в `localStorage` из кадра вернула `SecurityError`; устройство хранится только в
   памяти открытого окна.

Машиночитаемый протокол: `evidence/20260922-h106-manual-live.json`. Снимок после успешного
закрепления: `evidence/20260922-h106-manual-live.png`.

## Итог приёмки

Канонический транспорт H106 и временный обход §46 приняты в настоящем окне ОС.
Автоматическое определение устройства остаётся красным ровно на первом вызове из-за
маршрутизации H104. Это платформенный дефект §46; собственный код аккаунта на VPS и Mac
исполняется успешно. До исправления платформы продукт использует доказанный ручной путь.
