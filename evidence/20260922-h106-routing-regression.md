# H106: живой прогон в окне ОС — блок маршрута без `targets`

Дата: 22.09.2026  
Листинг: `40cf6ccf-10fe-4cd2-989f-702e5ddc8e8b`  
Версия: `0.1.0-pre.3`  
Агент установки: `agent_nz1ZRgpDnDKdAXLBABFOJ`  
Ожидаемое устройство: `24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4`

## Что подтверждено

- Страница открыта с рабочего стола настоящей Extella через CDP, не на стенде.
- `{{app_token}}` подставлен ОС.
- Покупке выданы `expert.run` и `device.run`.
- Первый запрос страницы имеет `expert_name=h106probe_where` и не содержит `targets`.
- Тот же `app_token` и тот же эксперт с
  `targets=[24f37e45-8c9f-4896-b64f-0dcd0cd8b0e4]` исполняются на Mac и возвращают
  `pageRoute.targetId`, `device` и `host=Anvars-MacBook-Pro.local`.
- Прямой `/api/expert/run` того же агента без `targets` тоже использует default target
  и возвращает тот же Mac.

## Где расходится платформа

`POST /api/app-agent/run` без `targets` не применяет default target агента. Он отправляет
эксперта в облачный Fython и возвращает:

```text
[Execution Error] invalid decimal literal (<container>, line 1)
```

В результате первый обязательный шаг H106 не получает `pageRoute.targetId` или `device`,
а страница правильно показывает человеку явную ошибку и оставляет повтор доступным.

Контрольный «Рекрутёр» и опубликованный «1С Agent AI» 22.09 дают тот же результат на
первом вызове без `targets`, поэтому причина не в коде нового диспетчера.

## Итог приёмки

Приёмка H106 пока красная ровно на первом вызове. Планку покрытия канона не обновлять,
пока `/api/app-agent/run` без `targets` не начнёт применять default target либо платформа
не даст странице другой scoped-способ получить устройство.
