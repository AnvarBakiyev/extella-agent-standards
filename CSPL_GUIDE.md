# CSPL: когда применять и как

Проверено живыми прогонами 27–28.08.2026. Всё, что названо работающим, запускалось на
платформе, а не в местной эмуляции: разница между «код написан» и «язык подключён» стоила
целого дня и описана здесь отдельно.

## Что такое CSPL

Эксперт — это **исходник плюс имя языка**. Поле `cspl` объявляет, на каком языке написан
исходник; по умолчанию `fython`. Обработчик языка — это отдельный контейнер на устройстве,
который получает исходник эксперта и делает с ним что угодно: исполняет, компилирует,
разбирает, рисует.

Отсюда главное свойство: **обработчик один на весь класс экспертов**. Правка обработчика
меняет поведение всех экспертов этого языка, ни один из них не переписан. Замер: три
эксперта на языке `sql` разом получили предел строк и маскирование телефона после
единственной правки обработчика.

## Когда применять: три семейства

| семейство | что в исходнике | безопасность даёт | когда брать |
|---|---|---|---|
| **протокол намерений** | имя операции и поля | политика клиента | доступ к чужой системе: база, почта, файлы |
| **узкий язык** | текст на ограниченном языке | грамматика | модель пишет исходник сама |
| **полный язык** | код на C, Go, Rust | доверенность кода | скорость, железо, готовые библиотеки |

**Протокол намерений** — когда сделка упирается в страх клиента, а не в нехватку
возможностей. Модель называет операцию, обработчик проверяет её по политике, которая лежит
у клиента и в промпт не попадает. Так устроен `one_c`.

**Узкий язык** — когда исходник пишет модель. Опасное не запрещается политикой, его
**нельзя выразить**: в языке `sql` нет слова `UPDATE`, в языке слайдов нельзя сказать
«выполни». Грамматика дешевле любой проверки и не зависит от настроек.

**Полный язык** — когда нужна скорость или библиотека, которой нет в fython. Грамматика
здесь не ограничивает ничего, поэтому код обязан быть доверенным: написан или проверен
человеком. Политика всё ещё решает, какие языки разрешены на устройстве, и держит пределы
времени и объёма ответа.

## Когда НЕ нужен свой язык

Если задача решается на `fython` — решать на `fython`. Свой язык оправдан тремя причинами:
сузить права до невыразимости опасного, получить чужой рантайм (компилятор, движок), либо
дать человеку читаемый исходник, который правится словами. Язык ради красоты добавляет
контейнер, который придётся сопровождать.

## Как подключить язык

Обработчик регистрируется обычным экспертом на `fython`:

```python
import disnet
d = disnet.Disnet(url="https://disnet.extella.ai")   # save_directory не задавать
конверт = {"filtered_source_code": "", "func_name": "", "args": None,
           "kwargs": None, "cspl": "<язык>", "response_format": None}
d.container(code=<исходник обработчика>, func_name="<язык>", container_path="<язык>",
            args=None, kwargs=конверт, cspl_type="fython", push=False)
```

Запускать регистрацию с закреплением за устройством: `targets=["<device_id>"]`.
Пять условий, без которых это ломается молча, перечислены в `DEPLOY_REQUIREMENTS.md`, H68.

## Как написать обработчик

Конверт, который приходит в точку входа (замерен 28.08.2026):

| поле | что содержит |
|---|---|
| `filtered_source_code` | исходник эксперта; **`code` приходит пустым** |
| `kwargs` | параметры запуска (`params` вызова) |
| `func_name` | имя эксперта, а не языка |
| `args`, `cspl`, `run_time` | служебные |

Обработчик обязан: принимать исходник из обоих полей; подставлять `{{параметры}}`; искать
внешний инструмент сам, потому что у службы урезанный `PATH`; возвращать словарь со
статусом и понятным текстом отказа.

Регулярные выражения в обработчике использовать не следует: обратные слэши не переживают
путь через fython, и проверка молча перестаёт работать — верный запрос отвергался как
неверный. Сравнение по словам надёжнее.

## Примеры, которые работают

**Узкий язык для чтения базы.** Эксперт `должники`, `cspl=sql`:

```sql
SELECT name, phone, amount FROM clients WHERE amount > 0 ORDER BY amount DESC
```

Запуск с параметрами `database`, `maxRows`, `maskColumns` вернул две строки с закрытыми
телефонами и честным признаком усечения. Эксперт с `UPDATE` в исходнике отклонён словами
«язык sql допускает только читающий запрос».

**Полный язык для расчёта.** Эксперт `считатель_долга`, `cspl=go`: разбирает строки,
считает итог и среднее, выносит вердикт. Отдал
`{"всего": 1680000, "клиентов": 3, "среднее": 560000, "вердикт": "долг превышает миллион"}`.

**Язык-документ вместо действия.** Эксперт `отчёт_по_долгам`, `cspl=slide`:

```
# Долги клиентов

## Итог по базе
!число {{млн}} | миллиона тенге всего долга
```

Обработчик экранирует весь текст, поэтому разметку в слайд не подставить: `<script>`
становится видимой строкой, а не кодом.

**Конвейер из несовместимых языков.** `sql` → `go` → `slide`: данные, расчёт, документ.
Ни одно звено не может вызвать другое; совместимость даёт общий договор — данные ходят
JSON-строкой. Это N языков вместо N×N мостов между ними.

## Что помнить при связывании звеньев

Платформа возвращает результат питоновским видом, а не JSON: разбирать нужно обоими
способами, иначе успешное звено выглядит отказом. Договор допускает пробелы в JSON —
наивный поиск подстроки `"total":` вернул нули при верных данных. Компилируемые языки
строги: неиспользованный импорт в Go роняет сборку, и это видно в тексте отказа, что
лучше молчаливого нуля.
