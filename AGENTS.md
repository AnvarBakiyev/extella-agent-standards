# Для ассистента, который здесь работает

Этот файл читают Codex и другие ассистенты, у которых нет механизма скиллов.
У Claude Code то же самое лежит скиллом `extella-ui`.

## Единый вход

`README.md` — что выполнять, что читать не выполняя. Дальше `DEPLOY_REQUIREMENTS.md`
раздел H и `BUILD_STAGES.md`.

## Если строишь интерфейс — сначала прочитай это

`skills/extella-ui/SKILL.md` целиком. Там правила понятности, дизайн-код Extella,
скелет экрана и чек-лист приёмки. Коротко, чтобы не отложить на потом:

- экран отвечает за пять секунд на три вопроса: где я, что можно, что делать первым;
- одна задача на экран, одно главное действие;
- четыре состояния нарисованы: пусто, идёт, отказ, готово;
- ожидание видно до вызова, снимается в `finally`;
- отказ говорит, что делать; «нет данных» — законный ответ;
- палитра, шрифты и шкалы заданы дизайн-кодом, свои не придумываются.

## Объём проверок берётся у машины

```bash
python3 tools/stage_gates.py --stage build --json
```

Проверки — это и есть спецификация. Текст рядом с ними объясняет причину, но
источником истины служит запуск.

## Что нельзя

Наружу — только черновики; данные клиента остаются в контуре клиента; без
разрушающих прав; чужое живое не трогать; секреты не едут в архив витрины; отказ
виден словами.

## Правило языка

`WRITING_RULES.md`. Всё, что прочитает человек снаружи команды, пишется по нему.
Проверяется машиной: `python3 tools/check_writing_style.py файл.md`.
